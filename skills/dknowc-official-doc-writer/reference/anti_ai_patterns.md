# 反 AI 味检查

用于正式文稿定稿前的语言复核，排查模板腔、旁白句、思考泄露、口语化、空泛套话和格式噪点。本文件只负责语言和表达模式，文种、事实、素材边界分别由 `reference/standards/*`、`reference/fact_discipline.md` 和 `reference/search_policy.md` 处理。

本文件属于质量建议层。除"思考泄露和起草过程"外，一般只提示风险，不直接判定文稿不可交付；是否调整取决于文种、用户模板和上下文。

## 检查方式

由模型通读全文后判断，不按固定词表自动替换。先定位反复出现的否定转折、递进并列、段落开头、高频词和固定搭配，再逐处读取前文、上下句和材料依据，只确认以下问题：

- **连续否定**：句中或相邻句出现两个以上否定分句时，保留材料明确且直接相关的必要否定，合并重复内容，省去主题外围的否定说明。
- **虚假对比**：两项内容并非相反、替代或递进关系，现有事实只支持其中一项，仍写成强对照或强递进。
- **机械重复**：同一词、固定搭配、句式骨架或段落开头集中复现，删减或改写不会损失办理逻辑和必要强调。

真实方案比较、法律政策要求、职责边界、风险提示、直接引语和必须统一使用的专业术语不按上述问题处理。不得自动批量替换，不得为避重复改动事实、引用、术语、否定范围和论断强度；不得把"未""不""不得"移到别的对象，也不得把"拟""建议""可"提升为"应""必须"或既定结论。

## 一、旁白句（写作说明混入正文）

检查说明"文章正在做什么"的句式，改为正文判断：

- `本方案重点说明三个问题` → 直接写结论
- `本文将从……` / `本节主要介绍` → 直接进入事实
- `以下直接列出` / `相关情况如下` → 直接列出事项
- `为了便于理解` / `简单来说` / `通俗地说` / `可以理解为` → 正式文稿通常不需要解释腔
- `根据有关资料显示` / `综上所述` → 核实来源后直接写事实，或直接写结论

## 二、思考泄露和起草过程（硬边界，必须删除）

以下表述属于硬边界，不得出现在正式正文：

- `作为AI……`、`我是AI……`、`由AI起草/生成`
- `我的思路是……`、`思考过程如下……`、`内部推理`
- `接下来我会……`、`我将根据……`、`按你的要求……`
- `这版文章……`、`这段文字……`、`根据用户要求修改如下……`

改为定稿表述：`项目拟……`、`经测算……`、`有关事项安排如下……`（仅文内过渡时）。

## 三、二元包装句

以下句式单独出现可保留（引用原文、法律边界、真实风险对照、明确办理层级时可保留），成簇出现且无事实支撑时提示调整：

- `不是……而是……`、`不仅……还……`、`不但……而且……`、`既……又……`、`一方面……另一方面……`

## 四、口号式收尾与空泛套话

以下词语并非一律删除，但必须有具体对象、机制、目标或结果支撑：

- `提供有力支撑`、`奠定坚实基础`、`再上新台阶`、`未来可期`、`形成一批`
- `重点任务包括`、`保障措施包括`、`总体看`（避免用总括句承接长清单）
- `高度重视`、`充分发挥`、`不断提升`、`持续推进`、`全面赋能`、`切实加强`

如果只是过渡填充，应删去或换成具体工作、责任、时限和成果。

## 五、高频抽象词节制使用

以下词只在指向具体机制时保留，同一词出现过多（一般为 3-6 次）时提示替换为更具体的名词：

- `口径`、`边界`、`底座`、`闭环`、`生态`、`抓手`、`矩阵`、`赋能`、`体系化`
- 可替换为：`服务`、`平台`、`系统`、`流程`、`资源`、`费用`、`数据`、`管理措施`

## 六、口语化与弱判断

常见替换方向（保持材料事实强度，不升级）：

- `更稳，也更省` → `成本和服务保障更具确定性`
- `用不完` → `阶段性资源余量`
- `AI味` → `表述偏泛、判断不够具体`
- `搞清楚` → `厘清`
- `老板关心` → `相关负责人关注该事项`，不无依据升级为`领导高度关注`
- `马上` → `立即`、`尽快`、`按时限推进`

口语来源不等于事实授权。`老板关心`、`钱花得值` 等只能说明材料中出现了关注或意向，不得自动升级成 `领导高度关注`、`投入产出清晰` 等强判断；如需正式化，用低强度表达，把程序、结论、时限和审批态度留给用户确认。

## 七、公文表达结构风险

以下问题属于质量建议层，只看成簇问题，不看孤立词。单独出现 `高度重视`、`一是二是三是` 或一次转折，不足以判为 AI 味；只有同时缺少对象、动作、责任、时限、数据或制度载体时，才提示压实：

- **夸大意义**：只写`意义重大`、`影响深远`，没有事项、对象、机制或数据支撑。
- **宣传腔**：把常规通知、报告写成表彰宣传稿，反复使用`成效显著`、`亮点纷呈`、`持续领跑`。
- **模糊归因**：写`有关方面认为`、`业内专家指出`，没有来源、主体或可核验事实。
- **公式化未来展望**：结尾只写`未来可期`、`再上新台阶`，没有下一步任务、责任、时限或反馈渠道。
- **同义词循环**：为避重复把同一主体反复换成`本项目`、`该平台`、`相关系统`，导致难以判断是否同一事项。
- **机械三段式**：固定套用`首先、其次、最后`或`一是、二是、三是`，每项只有态度没有事实。
- **过度抽象词互解**：用`赋能、生态、底座、矩阵、闭环`互相解释，没有具体工作、对象或验收标准。

修订方式：用具体事实替代抽象意义；用明确主体、动作、时限和责任替代泛泛判断；无来源的归因不当作正文事实；允许自然重复关键主体，不为避免重复而过度换词；保留公文必要正式语气，不引入第一人称、口语化、情绪化或公众号式"人味化"。

## 八、句群节奏

以下只作软性审稿项，不作为硬门禁。公文去 AI 味不是聊天化、散文化或规避检测；目标是让表达更克制、更具体、更贴近办理事项。不得为了显得"像人写"而加入第一人称、反问、口语插入、情绪化判断或故意不完美表达。

- **句首重复**：相邻段落反复以`要坚持`、`要强化`、`持续推进`、`下一步`、`同时`开头。
- **连接词链**：连续堆叠`同时、此外、进一步、最后、综上`，句与句之间没有事实递进。
- **句长同质化**：多个段落都是长度接近的长句或短句，重点不突出。
- **口号式收束**：每段都以`提供有力支撑`、`奠定坚实基础`、`推动再上新台阶`收尾。
- **清单堆叠替代论证**：整篇只靠`一是、二是、三是`排列态度，未说明事实依据、对象、机制和落点。

修订方式：保留公文骨架和用户模板，优先改句群节奏和信息密度，不随意重排标题层级；把重复连接词后的内容合并或改为事实递进；将口号式收束改为具体办理动作、责任时限、反馈渠道或审慎结论。

## 九、格式噪点

内容复核后再检查格式，尤其是 Word 文稿：

- 中文正文和数字之间是否有不必要空格。
- 普通中文正式材料中是否误用 `1,000,000` 千位分隔符。
- 中文正文一律使用全角标点，引号必须使用中文全角引号 `" " ' '`，禁止英文半角引号 `"` `'`；URL、代码、型号、英文缩写和公式可保留半角。模型生成正文时直接输出中文全角引号，不依赖排版脚本转换。
- 正文是否残留 Markdown 加粗 `**`、标题 `###`、横线 `---`、代码块包裹和 Emoji。
- 正文是否频繁使用 `1. 2. 3.` 西式编号；用户模板要求时可保留。
- 表格是否用于数据、进度、预算或责任清单，而不是逃避正文论证。

## 十、配合脚本

可运行 `python3 scripts/prose_lint.py <草稿文件> --format --structure` 扫描 `.txt`、`.md` 或 `.docx` 草稿。脚本只提示语言、格式和重复风险，不检查文种要素完整性，也不自动改写；不得把脚本结果作为不加判断的硬性清洗命令。
