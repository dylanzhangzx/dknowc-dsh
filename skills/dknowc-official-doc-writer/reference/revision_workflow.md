# 多轮改稿工作流

本文件处理用户基于已交付 Word 提出修改意见的连续改稿场景（"第二段太长""落款改一下""再加一节"）。改稿是真实使用中最高频的环节，核心目标是：**每轮只做用户要求的事，其余内容保持稳定，且不重复已完成的劳动。**

## 底稿锁定

- 每轮改稿以**最近一次交付的 Word 对应的正文**为唯一底稿；找不到底稿时（如新会话），先读取 `official-docs/output/` 中该任务最新版 `.docx` 提取正文，仍无法确定时向用户确认当前底稿。
- 严格版本递进：第 N 轮修改基于第 N-1 轮结果，不回退旧版正文；旧稿、参考样文只作结构或语气参考，其内容不得自动回流。
- 用户口头引用的旧稿片段（"把上一版那段加回来"）按用户明确要求处理，不算回退。

## 意见解析与逐条执行

- 先把用户本轮意见拆解为**结构动作**与**表达动作**两类：
  - 结构动作：增删自然段、调整段落顺序、替换/增删小标题、变更提纲、改变主送/落款/发文单位。
  - 表达动作：压缩、扩写、改语气、换措辞、改标题写法。
- 逐条执行，**先结构后表达**（先改正文结构，再统一润色语言，避免改了语言又动结构导致返工）。
- 每轮交付时用一两句话向用户汇报各条意见的落实情况；有未执行或变通执行的（如与文种规范冲突），明确说明原因。
- 用户没提到的段落**保持原样**，不借机"顺手优化"；确发现明显错误（错字、数据前后矛盾）可修正并在汇报中注明。

## 修改粒度对齐

- 用户说"补一句"只补一句或短句；"补一段"只补独立自然段；"新增一节/加个小标题"才新增标题层级。
- 不把句子级补充升级为新小节，也不把用户要求的小节压成普通句子。
- 用户要求"增加自然段"且未要求新增小标题时，保持原标题层级不变。
- 删除自然段或要点时删除完整结构单元，并检查相邻段落是否换词残留同一事项；调整顺序时同步更新小标题序号和前后衔接。

## 搜索与素材的复用

- **默认不重复搜索**：上一轮已完成的搜索结果（`official-docs/search-results/` 的 JSON 与素材确认结论）在本任务后续轮次中直接复用。
- 仅以下情况重新搜索，且须先向用户说明：
  - 用户明确要求换方向、换地域、换时间范围检索；
  - 用户新增的主题内容超出原搜索覆盖；
  - 用户质疑某条依据，需要核验或替换。
- 改稿不改变"执行过搜索须交付溯源 HTML"的规则：正文修改导致引用变化时，同步更新结构化 JSON 并重新生成 `标题_可信核验报告.html`；引用未变时可沿用上一轮报告，但在交付说明中注明。

## 偏好与事实边界的持续生效

- 每轮改稿前，已保存的写作偏好（`config/writing_preferences.json`）继续生效，scope 命中即应用；新轮次中用户纠正的习惯符合沉淀条件时，仍按"询问确认后保存"流程处理。
- 事实边界遵循 `reference/fact_discipline.md`：改稿只压实底稿已有事实和用户本轮补充的材料，不新增任何一方都没提供的责任、时限、数据；压缩时保留硬要素（对象、数字、期限、责任、联系人、落款）。
- 多轮累计的大改动（结构重排、新增章节超过原文三分之一）在执行前先列出改动清单请用户确认，避免大改后不符合预期。

## 交付

- 每轮改稿仍默认交付新版本 `.docx`（文件名自动追加 `_v1`、`_v2`），对话中只给文件路径和修改落实摘要，不粘贴正文全文。
- 用户明确要求"直接在对话里看改动"时，可只展示本轮修改涉及的段落（修改处前后对照），仍不全文粘贴。
