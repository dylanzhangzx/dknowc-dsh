# 深知搜索策略与素材规则

本文件是深知写作助手的稳定业务规则。可以优化 query 表达和检索覆盖，但不得改变素材分类、来源限制和素材使用闭环。

## 何时搜索

需要搜索：

- 用户提到政策背景、政策依据、政策支持
- 需要引用具体政策文件名、文号、标准或规范
- 涉及数据、指标、统计、案例或经验做法
- 用户明确要求根据某项政策、文件或地区实践起草
- 请示、复函、政策依据型报告等需要依据支撑的公文

通常不需要搜索：

- 纯工作部署，不涉及政策引用
- 内部事务通知，如会议通知、休假通知、时间地点变更
- 提醒函、告知函，且无政策依据要求
- 用户已提供充分材料，并明确要求只基于材料写作
- 通知、函、请示等短公文，如用户没有要求政策依据、数据或案例，默认不做大规模检索

如判断需要搜索，直接给出搜索方案并请用户确认；不要先问“要不要搜索”。在用户确认或调整搜索方案之前，不得执行搜索。如判断不需要搜索，说明理由并可直接进入写作，除非关键信息缺失。

## 检索预算

根据文种控制检索强度：

- 短公文：通知、函、请示、会议通知等，最多检索必要政策依据；没有明确依据需求时不检索。
- 常规长材料：总结、方案、汇报材料等，优先使用用户材料；确需支撑时检索 1-3 个关键方向。
- 研究型材料：调研报告、政策研究报告、产业研究报告等，可检索政策、数据、案例，但每类优先选择少量权威材料，不追求材料数量。
- 多地比较或专题研究：允许系统检索，但应先列明范围，避免一次性铺开过多地域和主题。

搜索完成后应做去冗余筛选，只将对正文判断有实质支撑的材料进入写作，不把全部搜索结果都写进正文或溯源核验报告。

## 搜索工具边界

本 Skill 的素材搜索按**两阶段执行（3.7.5 起）**，统一走脚本通道（需 API Key，3.7.5 起不再走 MCP）：

**阶段一·首轮深度搜索（广度召回）**
- 调用 `scripts/deep_query.py`（需 API Key）：
  ```bash
  python3 scripts/deep_query.py "搜索词" --area 地域 --json-only --output deep_路名.json
  ```
- 完整返回 JSON **立即落盘**到 `official-docs/search-results/deep_<路名>.json` 并 `json.load` 校验，再转换：
  ```bash
  python3 scripts/deep_convert.py official-docs/search-results/deep_<路名>.json --area 地域 --purpose "搜索目的"
  ```
  转换产物与 `--clean` 同构（顶层 `articles`、段落带 `id`）；真实返回**含快照（screenShotPath）、段落标题（标题链）、发布日期可信度**，如实保留；**缺独立"文号"字段**（文号在段落内容中），留待补搜匹配。

**阶段二·可信搜索补搜（精准补强，缺口驱动）**
- 深度搜索**缺独立"文号"字段**（政策文号在段落内容中）——**政策依据型必补搜**（补搜产出 policyFiles，正文引用政策文号靠其匹配）；数据/案例按研究资料口径表缺口（未给出/未确认/多口径未裁决）决定是否补搜。
- 补搜走可信搜索脚本 `dkag_search.py --clean`（参数见 SKILL.md 搜索命令节）。
- 补搜产物与深度搜索产物合并（`merge_search_results.py`）后进入素材分类；合并后按现有流程（素材四分类、研究资料、溯源报告）执行。

共同约束：query 构造（对象+关注方向，不列举信息需求）、素材四分类、补搜规则、地域边界在阶段一/二完全一致；阶段一深度搜索与阶段二补搜可信搜索统一走脚本通道。禁止默认使用以下工具或方式替代深知搜索：
- Web Search / Web Fetch / 浏览器搜索 / 公开官网抓取 / 通用搜索引擎

只有用户明确授权“改用 Web 搜索”“用公开官网检索”“不用深知搜索，网上查”等场景，才允许使用外部搜索。外部搜索结果必须单独标注为“公开网页补充材料”，不得写入【知识专库链接】，不得伪装为深知搜索素材。

如果深知搜索异常、空结果或素材不足，必须先暂停并请用户选择下一步，不得自行切换到 Web Search/Web Fetch（搜索脚本失败重试一次后仍失败，如实告知用户并暂停等待确认，不属切换外部搜索）。**例外（3.7.5 修复）：阶段一某一路深度搜索失败时，仅该路回退用可信搜索 `dkag_search.py` 重搜该路素材类型**（其他路不受影响、不整批回退），回退产物进入合并。

## 自由搜索（webSearch）使用边界

深知可信搜索另支持自由搜索渠道（全网检索，不限于政府站）。该渠道召回的基本是非官方来源（文档站、培训机构、聚合站等），且无存档快照、无发文字号，使用边界如下：

- 唯一用途：文风与体例参考（学"怎么写"：结构安排、开头结尾写法、句式和过渡语）。**定位是"参考范文召回的兜底"**：素材分类时若在已召回官方成文中发现了同类范文，优先走参考范文召回（取全文，见 `search_guide.md` 第四节）；**只有当官方库确无同类成文时**（第二节"写法参考"判断为"无"，如不常见的综合文稿、用户初次尝试的文种），才用本路从全网兜底搜同类文种写法——**经用户确认后执行**，不追求全文、搜到什么算什么。
- 严禁用途：政策依据、数据信息（统计数字、比例、金额、排名）一律不得使用自由搜索结果；正文事实层（人名、职务、机构、数字、政策条款）不得来自非官方材料。非官方页面上的转载数据不得使用，需回溯官方原发或放弃该数据。
- 非官方材料鉴别：使用前按"数据源 / 源网址域名"判断来源性质并显式标注；非官方范文常混杂过期文种标准和错误格式细节，与本地 `standards/` 冲突时一律以本地标准为准；范文站内容良莠不齐（AI 生成、拼凑、错字多），只取结构思路，不逐句模仿用语。
- 溯源边界：自由搜索素材不进入溯源核验报告（不占正文角标、不写入 materials 与 recalled_materials），也不生成知识专库链接。
- 执行参数：内部调用 `--search-channel webSearch`（无需搭配 `--search-type govSite`）；该参数不得出现在用户可见搜索方案中。
- 补开时机：已确认方案未含该路、写作中途发现文风参考不足时，可按素材充分性补搜规则补一路自由搜索（计入补搜次数，须向用户说明来源性质）。

## Query 生成原则

query 从**任务对象**出发构造——不从素材类目出发，也不从信息需求清单出发。分两阶段：

**启动 query（方案设计时）**——句式「`<对象>`（含地域、时间限定）的 `<关注方向>`」：

- 一句话的完整表述，**不列举具体信息需求**：不写"（产业规模、重点企业、存在问题…）"这类括号清单。列举会把检索面收窄到那几个词上，牺牲广度与召回质量；具体要哪些内容，交由深知搜索在对象范围内自行覆盖。
- 好例（国家级产业调研）：「我国机器人产业发展情况」
- 好例（省级政策）：「广东省人工智能产业政策」
- 坏例一（括号列举信息需求，禁止）：「我国机器人产业发展情况（产业规模与产值、重点政策文件、关键零部件与技术短板、存在问题）」——检索被括号里几个词框住，广度和质量同时下降。
- 坏例二（类目关键词堆砌，禁止）：「机器人产业发展规划 产业政策」——空格分隔的词组堆砌，不是一句话。
- 去掉"帮我写""生成一份"等写作指令词。
- 分路保留，各路只是**关注方向**不同：政策路写「…政策」，数据路写「…发展情况」，案例路写「…做法」；同一路内不叠加多维限定，一个对象配一个关注方向。

**补搜 query（缺口驱动，动态构造）**与启动 query 相反——**求精度不求广度**，从研究资料的数据口径表/纠错记录里出现的信息缺口出发（"未给出""未确认""多口径未裁决"必须触发补搜）：

- 句式带精确限定：时间+地域+对象/文件类型，如「巴彦淖尔市2026年草原补奖资金下达情况和乌拉特前旗2026年休牧公告原文」。
- 目标为原文级材料（公告原文、方案全文），不用主题句重复泛搜。
- 已知目标文件名时，直接用**标题原文**做 query（实测标题原文一发即中，关键词组合可能排不进前列）。

## 补搜自主与越界确认

- 搜索方案经用户确认后，其边界内（同一来源体系、同地域、同通道）的缺口补搜**自动执行，不逐次打断用户**——补搜以关键事实闭环为目标，不设次数上限，效果优先。
- 每次补搜的 query 与结果记入研究资料（口径表、纠错记录），交付时可回看——检索决策可核验。
- 越界必须停下确认：补搜需要新地域、换通道（如开 webSearch 自由搜索）、或循环后关键事实仍未闭环——停止并把缺口如实列给用户确认，不得自行改用其他来源。

## 搜索方案框架

执行搜索前必须向用户展示搜索方案，至少包括：

- 搜索地域：使用用户任务对应的国家、省或市，不预设具体地区。
- 搜索条件：**每条 query 的原文**（按"Query 生成原则"的启动句式构造）及其目的——用户确认的就是实际执行的句子，可直接修改。
- 素材类型：政策依据型、数据支撑型、参考案例型。
- 使用边界：哪些材料可作为政策依据，哪些只能作为案例或表述参考。
- 补搜说明：告知用户方案确认后，边界内的缺口补搜将自动执行并记入研究资料（越界会先确认）。

用户可见的搜索方案不得展示脚本参数、命令或输出文件名。不得出现 `--area`、`--search-type`、`--no-policy`、`--search-channel`、`--clean`、`--output` 等参数，也不得设置“参数”列或“参数：...”字段。参数选择属于内部执行细节，用户确认搜索方向和范围后，由 Agent 按本文件规则自行映射为深知搜索脚本调用。

不要为“表述参考型”单独设计 query 或单独搜索。表述参考来自政策依据、数据支撑、参考案例等已召回材料中的行文方式、结构和措辞，只能作为写作表达参考，不列入独立检索计划。

确认话术：

```text
我建议先按下面方案检索，请确认是否执行，或告诉我需要增删哪些搜索项。
```

用户确认后再执行深知搜索脚本；用户调整后，按调整后的方案执行。不得在确认后改用 Web Search/Web Fetch。

执行搜索时必须保留用户确认方案中的“搜索目的”。内部调用 `scripts/dkag_search.py` 时，将该搜索项的搜索目的传入 `--purpose`，脚本会写入 `search_meta.purpose`。`--purpose` 属于内部执行参数，不得出现在用户可见搜索方案中。

## 搜索执行节奏

同一次搜索方案内的多个搜索项默认并行执行（2026-09-20 起；历史上要求串行是因为并行会导致接口返回的知识专库链接错乱，该链接已不再进入溯源核验报告，障碍消除）：

- 每路搜索必须独立输出 JSON 文件（`--output` 分开命名），搜索目的独立传 `--purpose`；文件与目的一一对应，异常定位与溯源报告按 `search_key` 分组不因并行受影响。
- **结果即时落地是并行的前提，与路数无关**：每路调用返回后**立即**把完整返回 JSON 原样落盘并 `json.load` 校验通过，才发起下一路。**禁止"先把结果攒在对话里、整批完成后统一落盘"**——宿主对工具结果有清理机制，延迟落盘会"过期"丢失，路数越多越容易整批拿不到结果。
- 单次并行的路数上限为 4 路；超过时分批执行，上一批全部**落盘校验通过**后再发下一批——"上一批完成"以每路 JSON 文件存在且校验通过为准，不以"调用已返回"为准。
- 并行结束后逐路检查结果 JSON（`error` / `articles` 为空 / 字段异常），失败的路可单独串行重试一次，不得整批反复重发；落盘失败的路当场按落盘规则重写，不依赖从执行轨迹恢复（轨迹恢复只是最后手段，非常规路径）。
- 任意一路出现额度或余额用尽（`quota_exhausted=true`）时整批立即停止，按额度规则引导用户处理，其余路不再发起。
- 平台或接口明显限流（多路同时报错）时，回退为逐路串行执行，不反复尝试并行。

## 搜索异常处理

以下情况视为搜索异常或素材风险：

- 脚本返回 `error=true`
- 接口返回 `ret/errcode/code` 异常
- 网络、代理、API Key、权限、限流等错误
- 某个关键搜索项返回 `articles=[]`
- 关键材料类型缺失，如政策依据型或数据支撑型完全为空
- 召回材料缺少可回看通道（既无 `源网址` 也无存档快照）

出现上述情况时，必须暂停，不得直接进入正文生成，也不得自行改用其他来源。

**额度或余额用尽（`quota_exhausted=true`）单独处理：** 属于账户状态问题而非网络抖动，**禁止重试**——不得重发同一 query、不得换表述再搜、不得当作普通异常反复调用接口。立即告知用户积分或余额已用完，引导到 MaaS 管理平台 `https://platform.dknowc.cn/auth/#/login` 完成实名认证再领积分或充值；用户确认处理完成前不再调用深知搜索，可改用用户已有材料继续写作。

向用户说明：

- 哪个搜索项出现问题
- 已尝试的 query、地域、时间和参数
- 错误信息或空结果情况
- 其他搜索项是否已成功

然后请用户确认下一步，可提供这些选项：

- 重试当前搜索
- 调整 query、地域或时间后重试
- 跳过该搜索项，基于已成功素材继续
- 暂时不使用深知搜索，改为只基于用户提供材料写作
- 经用户明确确认后，改用 Web 搜索或公开官网检索补充材料

未经用户明确同意，不得自动执行 Web Search、Web Fetch、公开官网检索或浏览器搜索；不得自动跳过深知搜索；不得把公开网页检索结果写成深知搜索素材。

一、政策依据

- 国家级相关政策：单独 query，`--area 中国`
- 本省/直辖市相关政策：单独 query，`--area 省名/直辖市名`
- 本市相关政策：如适用，单独 query，`--area 市名`
- 政策依据型检索默认使用 `--search-type policy`；规范性文件清单（policyFiles，含发文字号）默认随结果返回，无需附加参数，加 `--no-policy` 可关闭（一般不关闭）。

二、数据支撑

- 本级整体数据：围绕现状、规模、进展、成效构造 query
- 下属行政区划数据：必要时按区县或部门分别构造 query
- 政府公开数据、工作进展、统计口径等，优先使用 `--search-type govSite --search-channel govSearch`，减少泛网页材料干扰。

三、参考案例

- 横向案例：同级可比地区的做法和经验
- 纵向案例：本地区历年同类工作的数据和做法
- 政府部门发布的案例、经验做法、工作动态，优先使用 `--search-type govSite --search-channel govSearch`。
- 政务事项、办事规则、流程口径类材料，使用 `--search-type affair`。
- `qa` 和 `private` 不作为默认公文写作搜索类型；只有用户明确要求常见问答或私有库材料时才使用。

四、附加参数

- 时间过滤：`--time` 仅用于明确的单个时间点或年份，如 `2025年`、`2025年08月`、`2025年08月15日`。不要使用 `2023-2025`、`2023年-2025年` 这类范围；需要覆盖多年时，优先不加 `--time`，或拆成多次单年检索。
- 规范性文件清单：默认随结果返回（`--no-policy` 关闭，一般不关闭）
- 搜索素材类型：使用 `--search-type` 指定，支持 `policy`、`affair`、`govSite`、`qa`、`private`。写作场景默认只使用 `policy`、`govSite`、必要时使用 `affair`。
- 动态搜索渠道：当使用 `--search-type govSite` 时，可加 `--search-channel govSearch`，优先召回政府官网、政务站点和官方渠道材料。`--search-channel webSearch` 为自由搜索（全网），仅限"文风与体例参考"场景且经用户确认后使用，边界见上文"自由搜索（webSearch）使用边界"，无需搭配 `--search-type govSite`。
- 全文召回：仅对参考范文使用 `--full`，不要同时加 `--clean`
- 段落数量：本 skill 固定使用 `segmentCount=2`，每篇材料最多返回 2 个相关段落
- 精简输出：本 skill 固定使用 `simplified=false`，用于写作场景保留更多候选材料，再由 Agent 做素材筛选
- 材料长度：脚本默认使用 `MaterialLength=12000`，控制单次召回材料总长度。除非用户明确要求深度研究或材料明显不足，不要主动调大。
- 指定数据源：`searchSourceUrl`、`searchSourceId` 当前不纳入默认流程。现有测试中该参数对召回范围约束不稳定，不得作为筛选指定官网或指定资料库的可靠手段写入搜索方案。

## 执行命令

单次搜索：

```bash
python3 scripts/dkag_search.py "搜索词" --area 地域 --time 时间 --clean --output result_地域.json
```

如无明确单个时间点，省略 `--time`：

```bash
python3 scripts/dkag_search.py "搜索词" --area 地域 --clean --output result_地域.json
```

多次搜索合并：

```bash
python3 scripts/merge_search_results.py result1.json result2.json --output merged.json
```

如需要补充政策文件全称或发文字号，可用文章标题补搜一次（规范性文件清单默认返回，从中取 writtenText 文号）。

政策依据型搜索：

```bash
python3 scripts/dkag_search.py "搜索词" --area 地域 --search-type policy --clean --output result_policy.json
```

政府站点动态、数据和案例搜索：

```bash
python3 scripts/dkag_search.py "搜索词" --area 地域 --search-type govSite --search-channel govSearch --clean --output result_govsite.json
```

政务事项、办事口径搜索：

```bash
python3 scripts/dkag_search.py "搜索词" --area 地域 --search-type affair --clean --output result_affair.json
```

## 素材四分类

搜索结果必须分类，不要把原始素材直接丢进正文生成。

分类后，必须继续按 `reference/material_usage_guidance.md` 判断材料如何进入正文。四分类解决“材料是什么”，材料使用指导解决“材料怎么用”；不得跳过这一层，直接拼接搜索摘要。

| 素材类型 | 允许的来源 | 用途 |
| --- | --- | --- |
| 政策依据型 | 仅国家级和本省 | 支撑正文政策依据、合法性、必要性 |
| 数据支撑型 | 仅国家级和本省 | 支撑现状、问题、成效、目标 |
| 参考案例型 | 其他省市或可比地区 | 借鉴做法、机制、经验，不作为本省政策依据 |
| 表述参考型 | 来自已召回材料 | 学习公文用语、结构和表达，不单独搜索，不在素材使用情况中单列 |

严禁将外省政策引用为本省公文的政策依据。外省材料只能作为参考案例或表述参考。

严禁将自由搜索（webSearch）召回的非官方材料用作政策依据或数据信息来源；其素材只作文风体例参考，不列入四分类的正式素材，也不进入溯源核验报告。

同一指标在不同材料中出现多个不同取值时，按 `reference/material_usage_guidance.md` 的同指标口径冲突检测处理：按材料发布日期取最新官方口径采用，不因旧口径素材数量占优而采用旧值。

## 素材充分性自检

搜索后自动评估：

- 政策依据：充足 / 较少 / 缺失
- 数据支撑：充足 / 较少 / 缺失
- 参考案例：充足 / 较少 / 缺失
- 表述参考：不作为独立搜索维度，不需补搜

不足时可在同一来源体系内补搜：常规材料按缺口适度补搜；研究型文种以关键事实（政策依据、核心数据）闭环为目标持续补搜，不设次数上限（效果优先）。补搜在已确认方案边界内自动执行（见"补搜自主与越界确认"）；越界或循环后仍未闭环时，停止并把缺口如实列给用户确认下一步，不得自行改用其他来源。

## 用户确认

完成搜索和自检后，应向用户展示：

- 搜索覆盖了哪些层级和地域
- 四类素材是否充足
- 是否所有被引用材料都有可回看的原文链接或存档快照
- 是否需要用户上传参考文件

用户确认素材可用后，再进入大纲或正文生成。

对所有正式写作任务，“正文生成”是内部写作步骤，不是聊天交付步骤。素材确认后应继续生成 Word（执行过搜索时另附 HTML 溯源核验报告），不得先把正文初稿或完整正文发给用户；除非用户明确要求“先看正文/先看草稿/不要生成 Word”。

## 参考范文召回

**触发条件**：在召回素材中发现某篇文章**与用户要写的材料高度相似**（同文种、同场景、体例接近），对其结构或论述逻辑有明确参考价值时，召回该篇全文作为写作参考。

**与范文大纲的关系**：两者并存、互不替代——范文大纲给出的是通用的结构建议，参考范文给的是同类成文实实在在的写法。大纲接口正常时照常走大纲确认；不因拿到参考范文而跳过大纲，也不因有大纲而放弃参考范文。

**操作要求**：

- **必须经用户明确同意**：先向用户推荐并等其确认，用户未回复/未同意/拒绝时不得取全文，按无参考范文继续写作
- 最多推荐 2 篇，优先 1 篇
- query 用**目标范文的完整标题**
- 使用 `--full`（这是本 Skill 中 `--full` 的唯一用途；不得用它补全政策全文）
- 不加 `--clean`（加了会丢弃"全文"字段）
- **只落盘目标那一篇**：接口会返回全部命中篇的全文，须按标题逐篇比对取第一篇命中的，用 `scripts/extract_reference.py` 提取并落盘；全量返回不作为参考范文留存

参考范文只学习结构和表达，不照搬内容；旧数据必须由写作素材中的新数据替换。参考范文不进入溯源核验报告（它只学写法，不作依据）。

## 写作交付

进入正文生成前，整理为“素材使用指引”：

- 每类素材标注用途：`用途：正文某部分`
- 写作素材和参考范文分开
- 表述参考只说明风格用途，不列入溯源核验报告
- 按 `reference/material_usage_guidance.md` 检查地域、时间、政策效力和数据口径风险

执行过搜索时，正式公文 Word 与素材溯源分开交付：

- 正式公文 Word：普通 Word 只包含用户要求的公文正文、必要附件、落款和版记，正文不内嵌 AI 生成提示；红头 Word 同样不保留 AI 生成提示，以免影响国标版记排版。正式公文 Word 不得内嵌 `【素材使用情况】`、`【知识专库链接】` 或知识专库 URL。
- 溯源核验报告：单独生成 `标题_溯源核验报告.html`，展示完整正文、可点击来源角标与来源卡片。**报告中不生成知识专库链接区**（该区已下线）；材料级溯源只使用素材自身的 `源网址` 与存档快照，逐条原样复制，不得用搜索会话级链接代替。来源卡片必须按正文位置、支撑内容和材料来源组织，体现已完成可信检索、来源定位和可追溯价值。溯源核验报告固定为 HTML，不生成 Word 版。最终 HTML 必须由 `scripts/source_note_html.py` 根据结构化 JSON 生成，模型不得手写页面或自行拼接链接、按钮和样式。

具体格式见 `reference/search_guide.md`。

交付边界：

- 素材使用指引、内部正文草稿、临时 Markdown 都属于生成 Word 的中间产物，不向用户发送。
- 所有正式写作任务默认交付 `.docx` 文件（执行过搜索时另附 HTML 溯源核验报告）。
- 聊天回复说明正式成稿路径；如生成溯源核验报告，作为辅助文件路径一并说明。
- 只有用户明确要求正文预览或不生成 Word 时，才可以在聊天中输出正文。
