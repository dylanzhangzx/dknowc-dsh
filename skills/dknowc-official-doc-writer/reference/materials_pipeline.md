# 素材清单、研究资料与溯源 JSON 流程

本文件是搜索之后的素材处理主流程：素材分类、素材清单落盘、研究资料初版/定稿、溯源 JSON 装配与校验。**执行过搜索的任务必读**；写作与产出物 HTML 以本文件产物为依据。

## 一、素材分类与素材清单

将召回素材分为四类：政策依据型、数据支撑型、参考案例型、表述参考型；表述参考型只能从已召回材料中归纳，不单独搜索。**写法参考（素材分类时必做判断，主备两级）**：逐篇归类时**必须**检查是否有**与目标材料同文种、同场景、体例接近**的成文（尤其同地域、同主题的报告/总结/调研），并在素材分类输出中**写明结论**（见 `reference/search_guide.md` 第二节分类模板的"写法参考"必填项）：

- **有 → 参考范文召回（首选）**：列出标题与推荐理由，按第 4 条子项与 `reference/search_guide.md` 第四节向用户推荐（**须经用户同意**方可取全文），取该篇**全文**作写法参考。
- **无 → 文风体例参考兜底**：明写"未发现高度相似的成文范文"，再按 `reference/search_guide.md` 第六节以 **webSearch 搜同类文种的结构写法**兜底（须经用户确认后执行）——只学写法、不作依据、不进溯源报告，搜到什么算什么，不追求全文。

两者是**同一目的的主备关系**（都只为学"怎么写"），不是并列的两种搜索：**先查官方库有没有同类成文，没有再用全网兜底**（常见误用是把二者当成并列或互斥关系，导致两级都未执行——既不查官方库，也不做 webSearch 兜底）。**素材清单先行（强制顺序）**：素材分类必须基于合并产物 `dknowc-output/${DSH_SESSION_ID:0:8}/official-docs/search-results/merged_all.json`（库内深搜＋补搜；触发降级时含联网/宿主 WebSearch 外部材料，均带通道与来源标记）（或等价合并文件）的**全量 articles 逐篇归类**，分类结果与合并产物一一对应、不得遗漏。**分类完成后必须把“选中的素材清单”落盘为 `dknowc-output/${DSH_SESSION_ID:0:8}/official-docs/input/materials_<任务>.json`**——顶层结构固定为 `{"task": "<任务名>", "doc_type": "<文种>", "selected": [ {…}, … ]}`；**每条 selected 必须带 `status`（现行/历史/参考）、`region`（本地/上级/外省/全国）两个字段**——同一事项存在多份文件时，`status=历史` 的那份只作沿革参考，不得作为正文依据；`region=外省` 的只能标“用法=借鉴”。缺这两个字段会被 `check_materials.py` 拦下（包括未被正文引用的 recalled 条目）。**`发布机关`（或 `发布或实施机构`）能填则填**：缺失不阻断，但来源卡不显示机构，`check_materials.py` 会给提醒。（用户明确字数要求时可在顶层加 `"length_target": {"min": 4000, "max": 5000}`；未提字数时不设默认区间，不校验篇幅）（**选中数组必须挂在顶层 `selected` 键下**，`build_trace_json.py` 按它读取，写成别的键会报"素材清单 selected 为空"；完整示例可运行 `python3 scripts/build_trace_json.py --sample <合并产物JSON>` 查看），每篇含 `type`/`标题`/`源网址`/`段落`/`发布日期可信度`/`快照链接` 标准字段，该清单是后续写作与溯源 JSON 的唯一材料依据。**禁止手工挑拣后直接写正文、禁止写完正文再反查用了哪些素材、禁止手写脚本/手写 JSON 定义 materials**（写完正文才反查材料、手工挑拣素材，会使正文引用无依据、溯源核验沦为"事后圆场"）。按 `reference/material_usage_guidance.md` 逐篇映射标准字段，字段缺失的如实留空并在核验报告中标注，不得凭记忆补造。

## 二、研究资料（初版与定稿）

对政策依据、数据支撑、参考案例做充分性自检；**研究型与综合长篇文种在本条生成研究资料初版**（把已合并检索产物消化为带角标的事实底稿——核心事实总表＋数据与口径表，落盘 `dknowc-output/${DSH_SESSION_ID:0:8}/official-docs/input/标题_研究资料.md`，规范见 `reference/research_notes.md`；短公文不启用），初版口径表/纠错记录出现信息缺口（未给出、未确认、多口径未裁决）必须触发补搜，补搜以关键事实闭环为目标、不设次数上限，在已确认方案边界内自动执行并记入研究资料；越界（新地域、换通道）或仍未闭环时停下向用户确认。

**用户确认素材清单后，再基于该清单写作正文**（强制顺序）：研究型与综合长篇文种（调研报告、政策/产业研究、综合性总结与汇报材料）**必须先把研究资料定稿再动笔**——更新第 8 条的初版（分主题详述按正文预定章节组织、角标与素材清单序号一致），**正文基于研究资料定稿写作**，短公文不启用；`check_materials.py` 对研究型文种缺研究资料文件将直接拒绝通过。正文按 `material_usage_guidance.md` 逐条引用清单材料，**写作时每处引用即标注 `[n]` 角标，n 对应素材清单序号**（先确认清单、边写边标，**禁止写完正文再反查/补标角标**）。正式写作任务不得把正文初稿作为聊天消息发出，直接生成产物：命中公文范式则生成 Word；执行过搜索则生成产出物 HTML（两者可同时成立）。

## 三、引用对照（正文写完、装配之前）

角标 `[n]` 只说明“引的是第 n 篇材料”，不能证明“这句话真的出自那一段”。写作完成后必须逐处落盘引用对照 `dknowc-output/${DSH_SESSION_ID:0:8}/official-docs/input/引用对照_<任务>.json`：

```json
{
  "task": "<任务名>",
  "citations": [
    {"mark": 3, "material": 3, "sentence": "正文中该角标所在的原句",
     "quote": "该句依据的原文片段（须在材料中逐字存在）", "用法": "依据"}
  ]
}
```

规则（**硬性，脚本校验；装配与渲染两处都会拦**）：

1. **逐处交付**：正文出现几次 `[n]`，就要有几条对应记录（同一材料多处引用＝多条），缺一条 `build_trace_json.py` 直接报错。
2. **`material` 必须等于 `mark`**：角标号就是素材清单序号，写成别的数字等于拿另一篇材料顶替，直接报错。
3. **`sentence` 必须照抄正文原句并含角标本身**：例如 `……工作。[3]`，句子里要带 `[3]`。只写句子、不写角标，无法证明它对应哪一处引用。同一角标在正文出现多次时，**每条必须对上是第几处**——两处都是 `[3]`，第一条要抄第一处的句子、第二条抄第二处的，两条都抄同一句会被判为错位。
4. **`quote` 必须逐字取自该材料，且不少于 10 字**：脚本去掉空白/全半角差异后做包含比对，找不到或过短均失败——防止“引文是编的”“拿一段原文去套不相干的句子”和“用几个字的通用短语蹭命中”。
5. **用法只填「依据」或「借鉴」**：`region=外省` 的材料只能填“借鉴”，并在正文写明是外地做法；填“依据”直接失败。
6. **`status=历史` 的材料不得出现在引用对照里**：同一事项已有更新文件时，正文只能引现行版本。
7. **渲染前还有一道同样的校验**：`source_note_html.py` 生成 HTML 前会重跑上述校验（含 quote 原文比对），不通过直接退出——不是“记得跑校验”，而是跳过校验也出不了报告。**引文原文比对必须有合并产物**：溯源 JSON 的 `merged_json` 指向的文件缺失或读不出时直接拒绝渲染（不降级），恢复合并产物或重新装配后再渲染。

装配与校验命令：

```bash
python3 scripts/build_trace_json.py <素材清单> <正文> <合并产物> --title "<标题>" --output <溯源JSON>
python3 scripts/check_materials.py <溯源JSON> <合并产物>
```

`build_trace_json.py` 会把每处引用挂到对应材料（`materials[].citations`），作为逐字校验与逐处对应的数据底座；报告弹层展示该材料的原文原段（含被引用段落与章节位置），供逐句比对。

## 四、溯源 JSON 装配与校验

产出物 HTML 必须按 `reference/search_guide.md` 的固定流程生成：**用 `scripts/build_trace_json.py` 从"素材清单 + 正文（带角标）"装配溯源 JSON 到 `dknowc-output/${DSH_SESSION_ID:0:8}/official-docs/input/标题_溯源核验报告.json`**（materials 按正文角标序对应素材清单、recalled_materials 自动取清单未引用部分 + 合并产物未选部分、self_check 骨架待填），再调用 `python3 scripts/source_note_html.py ...` 输出产出物 HTML（正文 / 溯源核验报告 / 知识专库 三页）。**用户原问题全文必须写入溯源 JSON 的 `question`；多行/长 prompt 先落盘，用 `--question-file` 传入，禁止只传首行**（只传首行会导致报告页“原问题”丢失其余要求）。**字段契约**：溯源 JSON 必须包含 `document_content`（带 `[n]` 角标）、`materials`（全量引用材料，含标准字段）、`recalled_materials`（全部未引用召回材料，不得留空）、`self_check`（五项检查结果按**两轨验收的结构化契约**写入，见第五节——每项 `{verdict, basis, evidence}`，裸写"通过"会被拦截）；生成 HTML 前必须运行 `python3 scripts/check_materials.py <溯源JSON> <合并产物JSON>` 校验（材料来源可回溯、字段完整、角标一一对应、recalled 非空），**校验通过后才允许调用渲染脚本**。`document_content` 必须在关键结论后标注 `[1]`、`[2]` 等角标并逐条对应 `materials`——脚本会校验，正文无角标时拒绝生成并报错，必须修正 JSON 后重跑，不得省略角标直接交付。不得由模型手写完整 HTML，不得自行拼接 `<a>`、`onclick`、按钮、卡片或页面样式。

## 五、两轨验收（报告合格线）

产出物 HTML 的合格判定是**两轨合流**：**结构核验（脚本轨）∧ AI 验收（Agent 轨）**。任一轨不过，渲染器直接退出、**不产出 HTML**——交付物只有"已核验"一种形态；发现问题就修正后重跑，不是把带问题的报告交给用户。

**脚本轨只判结构**（不做内容判断）：正文每个角标都绑定到材料、每条正文依据有可展开的原文摘录、不可引用材料不作依据；引用逐字比对、版本效力与地域用法由第三节引用对照与 `check_materials.py` 兜住。数字、标准号、地域、缺席内容、金额对象、措辞等**内容类判断全部归 AI 验收**，脚本不据此判红。

**Agent 轨（AI 验收）**：`self_check` 五项（`事实有据` / `结构完整` / `无占位残留` / `无AI味` / `格式合规`）逐项按结构化契约提交：

```json
"self_check": {
  "事实有据": {"verdict": "pass", "basis": "关键结论逐条对照素材清单核过",
               "evidence": ["[1] 每千人口托位数 4.5 个出自该文件第二段", "成文日期 2026-11 与最新文件一致"]},
  "格式合规": {"verdict": "pending", "basis": "发文字号待正式编号后回填", "evidence": ["文号 字〔2026〕1 号留空待编"]}
}
```

硬约束（违反即被渲染器拦截，报告出不来）：

1. **键名只用这五个中文键**，英文键与"备注"等额外键都不构成核验项。
2. **每项必须给 `verdict`（pass/fail/pending）+ `basis`（结论依据）+ `evidence`（证据数组）**。
3. **证据必须可回查**：`evidence` 里至少要有材料角标 `[n]`／条款号（第X条）／发文字号（〔2026〕X号）／日期／文件名／GB 标准号等任一要素——声明"通过"但证据里没有这些要素，按结构违约（证据不足）拦截，**裸写"通过"同样拦截**。
4. **`fail` 是否决**：先解决问题再出报告；**`pending` 只表示待人工复核**，可出报告但如实标注，不算未通过。
5. **AI 验收按"事实有据"实质判断**：逐条对照素材清单核对其撑没撑住正文表述，不得只做字面搜索或全填 pass。自检发现未闭环项应先补搜闭环，补不到才停下与用户确认，不得带缺口直接生成报告。

## 六、源网址字段

整理 `materials` 时，凡来自深知可信搜索的材料，必须将原始结果中的 `源网址` 原样写入 `source_url`；不得只写规范化后的文章标题，再依赖标题反查网址。若接口未返回 `源网址`，该材料不显示原文链接；不得猜测、补造或用搜索接口地址代替。

搜索**技术异常**（脚本返回 `error=true`、接口/网络/权限异常）时立即停止后续写作，说明失败路与已成功路，请用户确认下一步（重试/调整/跳过/改用已有材料）；**关键路空结果属素材缺口，按三阶段降级链处理**（`reference/search_policy.md`），不停止写作。**额度用尽（`quota_exhausted=true`）禁止任何重试**，引导用户到 MaaS 平台处理后继续；用户确认前不再调用搜索。降级链内的联网模式与宿主 WebSearch 是规则内置路径，不属于“擅自改用”。

外部检索口径：库内缺口按 `reference/search_policy.md` 三阶段降级链触发外部检索（联网模式 → 宿主 WebSearch），外部材料一律经 `websearch_convert.py` ＋ `merge_search_results.py` 管线并入并带「非官方来源」标记，不得绕过管线手抓网页；规则之外的外部检索（如用户明确要求"用公开官网检索"）同样必须说明这些材料不是深知搜索结果；从深知搜索返回链接取全文也必须先经用户确认。外部材料不得伪装为深知搜索结果。


搜索方案要素与展示边界（地域/内容/素材类型/使用边界，禁止出现脚本参数）见 `reference/search_policy.md` 与 `reference/search_guide.md` 第三节。


搜索方案确认话术：

```text
我建议先按下面方案检索，请确认是否执行，或告诉我需要增删哪些搜索项。
```

搜索命令与参数（**统一走脚本通道**，需 API Key）：脚本调用、参数映射、searchType 单值分路、时间与段落参数、合并命令均见 `reference/search_policy.md` 执行命令节。宿主当前目录不在 skill 安装目录时，一律改用 skill 安装目录的绝对路径调用；搜索结果只能读写 `dknowc-output/${DSH_SESSION_ID:0:8}/official-docs/input|output|search-results/`。
