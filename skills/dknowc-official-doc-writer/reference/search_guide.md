# 搜索流程详细指南

本文件包含搜索流程中的格式模板和输出示例，供 AI 执行搜索相关步骤时参考。

---

## 一、范文大纲搜索建议承接

如果本轮已调用 `scripts/outline_reference.py` 且返回可用大纲，必须先由用户确认大纲和搜索建议。用户确认后，再把接口返回的 `search_suggestions` 转化为深知搜索方案。

处理原则：

- `search_suggestions` 只是检索方向，不是已检索素材。
- 搜索方案仍需按政策依据型、数据支撑型、参考案例型拆分。
- 不得把大纲接口返回内容写入溯源核验报告，也不得生成知识专库链接。
- 不得在用户可见方案中展示大纲接口 JSON、保存路径或脚本参数。
- 如用户修改大纲，应按修改后的结构重新设计搜索方案。
- 调用大纲接口时必须传入用户原始写作需求的完整表述，不得只传压缩标题，否则容易返回“未检索到可用范文”。
- 大纲和搜索建议的用户确认内容必须分节展示，不得压成一整段。

大纲确认展示模板：

```text
我先根据范文库生成了参考大纲和后续搜索建议，请确认是否按这个结构继续，或告诉我需要调整哪些部分。

建议大纲：

一、XXX
- 写作目的：……
- 主要要点：
  - ……
  - ……

二、XXX
- 写作目的：……
- 主要要点：
  - ……

后续搜索建议：

1. 政策依据
- 检索方向：……
- 用途：……

2. 数据支撑
- 检索方向：……
- 用途：……

3. 参考案例
- 检索方向：……
- 用途：……
```

用户确认大纲后的搜索衔接话术：

```text
我会基于已确认的大纲，把其中的搜索建议转化为政策、数据和案例检索方案。请确认下面的检索方案是否执行，或告诉我需要增删哪些搜索项。
```

## 二、搜索结果分类输出格式

所有搜索完成后，AI 对全部素材按以下格式分类输出：

```
【搜索结果分析】

素材统计：共召回 X 篇文章，Y 个相关段落

分类结果：

**1. 政策依据型**
- 《XX管理办法》（文号）- 可引用条款
- 《XX实施细则》（文号）- 可引用条款
  → 共 N 篇

**2. 参考案例型**
- XX省做法：...
- XX市经验：...
  → 共 N 篇

**3. 数据支撑型**
- 统计数据：XX年达到XX
- 调研结果：...
  → 共 N 个数据点

说明：表述参考型不作为独立搜索类型，不单独列入搜索方案。需要学习表达时，只能从已召回的政策依据、数据支撑、参考案例材料中吸收行文方式。

素材充足度评估：
- 政策依据：充足 / 较少 / 缺失
- 参考案例：充足 / 较少 / 缺失
- 数据支撑：充足 / 较少 / 缺失
- 表述参考：不单独搜索，从已召回材料中吸收
```

## 三、搜索方案展示模板

执行深知搜索前，先向用户展示搜索方案并等待确认。用户可见的搜索方案只写检索方向、地域、素材类型、检索内容和用途，不展示脚本命令、参数或文件名。

禁止在用户可见方案中出现以下内容：

- `--area`、`--search-type`、`--policy`、`--search-channel`、`--clean`、`--output` 等脚本参数
- “参数”列或“参数：...”字段
- `python3 scripts/dkag_search.py ...` 形式的命令
- 输出文件名、JSON 文件名或内部保存路径

```
【搜索方案】

搜索地域：任务所在地区 / 中国

1. 政策依据
- 地域：某省
- 检索内容：某省人工智能产业政策支持
- 用途：查找可作为本省政策依据的文件、意见、办法等

2. 数据支撑
- 地域：某省
- 检索内容：某省人工智能产业发展规模、产业数据和工作进展
- 用途：查找政府公开发布的产业数据、工作进展和成效

3. 参考案例
- 地域：中国
- 检索内容：人工智能产业发展典型做法和应用案例
- 用途：查找可借鉴的政府部门案例和经验做法，不作为本省政策依据

说明：表述参考不单独搜索，将从上述材料中吸收公文表达和结构。
```

用户确认后再执行搜索；如用户调整地域、query 或素材类型，按调整后的方案执行。执行时必须把每条搜索项的“搜索目的”作为内部 `--purpose` 传给搜索脚本，用于检索目的记录；不得把 `--purpose` 展示给用户。

内部执行时，Agent 再自行选择对应脚本参数并调用 `scripts/dkag_search.py`。内部参数选择不得要求用户理解，也不得作为搜索方案的一部分展示。多个搜索项默认串行执行：上一项搜索完成、结果 JSON 写入并完成异常判断后，再执行下一项。不得并发调用多个搜索请求，也不得使用后台任务或多 Agent 同时检索，除非用户明确要求并确认可接受并发风险。

## 四、参考范文召回流程

### 步骤1：向用户推荐

```
【参考范文推荐】

在搜索素材中发现一篇文章对成文结构有重要参考价值：

《文章标题》
来源：XX，作者，日期
参考价值：[说明参考什么，如"文章结构与我们的报告高度吻合，可学习其论述逻辑"]

确认获取全文作为参考范文吗？（是/否）
```

### 步骤2：用户确认后，用文章标题全文召回

```bash
python3 scripts/dkag_search.py "[文章完整标题]" --full
```

注意：不加 `--clean`！加了会丢弃"全文"字段。

### 步骤3：从返回结果中提取目标文章

API 会返回多篇全文，必须按标题精确匹配，只提取目标文章的"全文"字段：

```python
for article in result['content']['data']['检索文章']:
    if article['文章标题'] == '目标文章标题':
        full_text = article['全文']
        break
```

### 步骤4：确认提取成功后告知用户

```
【参考范文已获取】

《文章标题》
来源：XX，作者，日期
字数：约XXXX字
已提取全文，将在撰写时作为参考范文使用。
```

提取失败时告知用户，回到步骤1重新选择或跳过。

## 六、溯源核验报告 HTML

执行过搜索时，正式公文 Word 不在正文中添加来源角标、素材清单和知识专库链接。撰写完成后，单独生成 `标题_溯源核验报告.html`：报告打开第一屏即展示核验报告单（依据溯源、引用对应、材料新旧、材料构成、交付前检查五项指标，文案为自然说法），正文按章节分卡片展示并把 `[1]`/`【1】`角标变成可点击的来源跳转；右栏为核验材料面板：每张材料卡展示接口返回的原文标题链（如"标题：一、重点支持方向 › 方向2…"，即该段在原文件中的章节位置）、摘录块上方标注"▍ 原文原段（非 AI 生成）"、发布日期可信度为"高"的材料加"高可信"徽标、超 4 行摘录折叠并显示"展开全文"；多路检索时面板顶部按搜索条件生成筛选胶囊（单选 + 全部，另有"未引用"一项）；接口召回但正文未采用的相关材料进入"未引用素材"分组（不占正文角标编号，标"可查看原文"而非"已核验"）；移动端点正文角标弹出"正文表述 ↔ 原文原段"上下对照弹层。报告固定为 HTML，不生成 Word 版。

生成方式：

1. 先将核验报告整理为结构化 JSON，保存到 `official-docs/input/标题_溯源核验报告.json`，其中正文写入 `document_content`，正文引用使用 `[1]`、`[2]` 等角标——这是硬性要求：materials 非空时正文必须带角标并一一对应，`source_note_html.py` 校验到正文无角标会拒绝生成并报错，须修正 JSON 后重跑。
2. 再调用 `scripts/source_note_html.py` 生成 HTML：

```bash
python3 scripts/source_note_html.py official-docs/input/标题_溯源核验报告.json --output 标题_溯源核验报告.html
```

未指定目录的 `--output` 会保存到 `official-docs/output/`。也可以显式写为：

```bash
python3 scripts/source_note_html.py official-docs/input/标题_溯源核验报告.json --output official-docs/output/标题_溯源核验报告.html
```

生成边界：

- 必须使用 `scripts/source_note_html.py` 生成最终 HTML；模型只负责准备结构化 JSON，不得手写完整 HTML 页面。
- 不得自行拼接 `<a>`、`onclick`、按钮、卡片、CSS 或整页 HTML；不得用 Markdown、Word 排版脚本、浏览器保存网页等方式替代。

格式要求：
- 正式公文正文中不得包含 `【素材使用情况】`、`【知识专库链接】`、知识专库 URL 或素材清单。
- 溯源核验报告 HTML 是辅助核验文件，不是正式公文附件，不附在正式正文后；它包含核验报告单、完整正文和可点击溯源交互。
- 报告不再包含知识专库链接区：未引用召回材料已全量进入材料面板，完整召回在报告中即可回看；JSON 中无需 `knowledge_bases` 字段（残留该字段会被忽略）。
- `self_check` 为必填字段：把成稿快速自检的 5 项结果（`fact_basis` 事实有据 / `structure` 结构完整 / `placeholders` 无占位残留 / `ai_flavor` 无 AI 味 / `format` 格式合规）如实写入，通过写 `"pass"`，未通过写 `"fail"`；不得省略，也不得未检查就填 `pass`——核验单展示的就是这 5 项，如实填写是报告可信的前提。
- `materials[].type` 使用四分类取值：`政策依据型` / `数据支撑型` / `参考案例型` / `表述参考型`，报告按类型分色展示并支持筛选；类型缺失时材料卡降级为灰色"材料"。
- `materials` 中每条素材至少包含 `material_name`、`source`、`section`、`support`；来自深知可信搜索的材料还必须把原始结果的 `源网址` 原样写入 `source_url`，不得依赖规范化标题反查。接口未返回原网址时不填、不猜测。存在数据口径、发布日期、文号或强判断时，应补充 `verification`，并使用“已完成……核验”口径，不得写“建议核对”“需人工核验”“以官方最新口径为准”等削弱可信度的措辞。
- `materials[]` 与 `recalled_materials[]` 每条必须带 `search_key`（该材料来自哪一次搜索的阅读友好名，如“北京·养老政策”；同一次搜索的材料用同一个 key）。多路检索时报告据此在材料面板生成检索筛选胶囊，单路检索时自动隐藏。
- 整理 JSON 时必须把接口返回的 `段落`（含每段 `标题` 与 `内容`）和 `发布日期可信度` 字段**原样保留**到对应素材：段落标题用于材料卡的“标题：…”原文位置链（标注该段在原文件中的章节位置），可信度为“高”时材料卡展示“高可信”徽标。丢弃这些字段会导致报告缺失标题链与质量标识，属整理失误。
- `recalled_materials` 放接口召回但正文未采用的相关材料：排除明显无关的文章后**全量放入**，不做人工精选——供用户检查“没采纳的有没有更好”。结构与 `materials` 相同（含 `search_key`、`段落`、`source_url`）。未引用材料缺 `source_url` 时照实不填，报告在其卡片标注“待补链接”；“依据溯源”与“已核验”只统计正文引用的材料，未引用材料不影响核验结论。
- 核验单中的"依据溯源""引用对应"由脚本按 JSON 与正文自动计算：素材缺 `source_url` 或摘录、正文角标无对应素材时，核验单会如实显示待补与未绑定，因此整理 JSON 时必须保证素材与角标一一对应。
- 每条素材只写实际用于正文的核心依据，不机械罗列所有搜索结果；同类材料可合并说明，避免来源说明变成流水账。
- 不得使用表格承载素材使用情况；HTML 由脚本生成卡片式布局。
- 不得使用 `→ 用于：`、箭头符号或其他内部工作流标记。
- 写作素材和参考范文分开列出。
- 参考范文只写 `参考用途：` 和 `使用边界：`，不得把表述参考混入写作依据。
- HTML 由 `scripts/source_note_html.py` 生成；不要手写完整 HTML 页面，也不要用 Word 排版脚本生成溯源核验报告。
