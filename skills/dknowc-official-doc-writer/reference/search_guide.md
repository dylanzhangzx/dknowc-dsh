# 搜索流程详细指南

本文件包含搜索流程中的格式模板和输出示例，供 AI 执行搜索相关步骤时参考。

---

## 一、范文大纲搜索建议承接

如果本轮已取得范文大纲（统一用 `scripts/outline_reference.py`，需 API Key）且返回可用大纲，必须先由用户确认大纲和搜索建议。用户确认后，再把接口返回的 `search_suggestions` 转化为深知搜索方案。

处理原则：

- `search_suggestions` 只是检索方向，不是已检索素材。
- 搜索方案仍需按政策依据型、数据支撑型、参考案例型拆分。
- 不得把大纲接口返回内容写入溯源核验报告，也不得生成知识专库链接。
- 不得在用户可见方案中展示大纲接口 JSON、保存路径或脚本参数。
- 如用户修改大纲，应按修改后的结构重新设计搜索方案。
- 调用大纲接口时必须传入用户原始写作需求的完整表述，不得只传压缩标题，否则容易返回“未检索到可用范文”。
- 大纲和搜索建议的用户确认内容必须分节展示，不得压成一整段。

大纲确认展示模板：

```text
我先根据范文库生成了参考大纲和后续搜索建议，请确认是否按这个结构继续，或告诉我需要调整哪些部分。

建议大纲：

一、XXX
- 写作目的：……
- 主要要点：
  - ……
  - ……

二、XXX
- 写作目的：……
- 主要要点：
  - ……

后续搜索建议：

1. 政策依据
- 检索方向：……
- 用途：……

2. 数据支撑
- 检索方向：……
- 用途：……

3. 参考案例
- 检索方向：……
- 用途：……
```

用户确认大纲后的搜索衔接话术：

```text
我会基于已确认的大纲，把其中的搜索建议转化为政策、数据和案例检索方案。请确认下面的检索方案是否执行，或告诉我需要增删哪些搜索项。
```

## 二、搜索结果分类输出格式

所有搜索完成后，AI 对全部素材按以下格式分类输出：

```
【搜索结果分析】

素材统计：共召回 X 篇文章，Y 个相关段落

分类结果：

**1. 政策依据型**
- 《XX管理办法》（文号）- 可引用条款
- 《XX实施细则》（文号）- 可引用条款
  → 共 N 篇

**2. 参考案例型**
- XX省做法：...
- XX市经验：...
  → 共 N 篇

**3. 数据支撑型**
- 统计数据：XX年达到XX
- 调研结果：...
  → 共 N 个数据点

说明：表述参考型不作为独立搜索类型，不单独列入搜索方案。需要学习表达时，只能从已召回的政策依据、数据支撑、参考案例材料中吸收行文方式。

素材充足度评估：
- 政策依据：充足 / 较少 / 缺失
- 参考案例：充足 / 较少 / 缺失
- 数据支撑：充足 / 较少 / 缺失
- 表述参考：不单独搜索，从已召回材料中吸收

写法参考（**必填项，逐篇归类时判断，不得省略；主备两级**）：
- **有同类官方成文 → 参考范文召回（首选）**：列出与目标材料**同文种/同场景/体例接近**的成文（如目标为「某市优化营商环境调研报告」时，召回中的《XX市营商环境发展报告》即属同类），写明标题与推荐理由 → 按第四节向用户推荐、经同意后取该篇**全文**
- **无 → 文风体例参考兜底**：写明"未发现与目标材料高度相似的成文范文" → 按第六节以 webSearch 搜同类文种的结构写法（经用户同意后执行），只学写法、不追求全文
```

**说明**：本节是**同一目的（学"怎么写"）的主备两级**，不是并列的两个搜索项——**先查官方库有没有同类成文（首选、取全文），没有再用全网 webSearch 兜底（只学写法、不追求全文）**。2026-09-28 两次实测均因把二者当成并列/互斥关系而未触发（一次跳过 webSearch 未做、一次开了 webSearch 也未做）。

## 三、搜索方案展示模板

执行深知搜索前，先向用户展示搜索方案并等待确认。用户可见的搜索方案只写搜索条件、地域、素材类型和用途，不展示脚本命令、参数或文件名。

禁止在用户可见方案中出现以下内容：

- `--area`、`--search-type`、`--no-policy`、`--search-channel`、`--clean`、`--output` 等脚本参数
- “参数”列或“参数：...”字段
- `python3 scripts/dkag_search.py ...` 形式的命令
- 输出文件名、JSON 文件名或内部保存路径

```
【搜索方案】

搜索地域：任务所在地区 / 中国

1. 政策依据
- 地域：某省
- 搜索条件：某省人工智能产业政策
- 用途：查找可作为本省政策依据的文件、意见、办法等

2. 数据支撑
- 地域：某省
- 搜索条件：某省人工智能产业发展情况
- 用途：查找政府公开发布的产业数据、工作进展和成效

3. 参考案例
- 地域：中国
- 搜索条件：各地人工智能产业发展做法
- 用途：查找可借鉴的政府部门案例和经验做法，不作为本省政策依据

说明：表述参考不单独搜索，将从上述材料中吸收公文表达和结构。方案确认后，边界内的缺口补搜自动执行并记入研究资料；越界（新地域、换通道）会先向您确认。
```

用户确认后再执行搜索；如用户调整地域、query 或素材类型，按调整后的方案执行。执行时必须把每条搜索项的“搜索目的”作为内部 `--purpose` 传给搜索脚本，用于检索目的记录；不得把 `--purpose` 展示给用户。

内部执行时，Agent 统一走脚本通道（需 API Key，3.7.5 起不再走 MCP），**两阶段（3.7.5 起）**：阶段一用 `scripts/deep_query.py`（返回落盘后 `scripts/deep_convert.py` 转换）、阶段二补搜用 `scripts/dkag_search.py`。内部参数选择不得要求用户理解，也不得作为搜索方案的一部分展示。同一次方案内的多个搜索项默认并行执行（每路独立 `--output` 与 `--purpose`，单批不超过 4 路），单次调用内用后台任务并行、`wait` 等全部结束后逐路检查结果；失败路单独串行重试一次，任意一路余额用尽即整批停止（详见 `reference/search_policy.md` 搜索执行节奏）。

## 四、参考范文召回流程

**触发时机**：在**素材分类阶段**（SKILL.md 搜索规则第 5 条逐篇归类时）判断——在已召回材料中发现与目标材料**同文种、同场景、体例接近**的**官方成文**时触发（**首选路径**）。若未发现，改由第六节"文风体例参考"从全网兜底。两者是**同一目的（学"怎么写"）的主备关系**，不是并列选项。

**前置要求（强约束）：取全文必须经用户明确同意。** 在调用 `--full` 之前，必须先按步骤1 向用户推荐该篇并取得明确同意（用户回复"是/可以/获取"等）；**用户未回复、未同意或拒绝时，不得调用 `--full`**，直接按无参考范文继续写作（这不影响大纲与正文生成）。不得擅自取全文、不得不经确认就执行步骤2。

### 步骤1：向用户推荐

```
【参考范文推荐】

在搜索素材中发现一篇文章对成文结构有重要参考价值：

《文章标题》
来源：XX，作者，日期
参考价值：[说明参考什么，如"文章结构与我们的报告高度吻合，可学习其论述逻辑"]

确认获取全文作为参考范文吗？（是/否）
```

### 步骤2：用户确认后，用「目标范文的完整标题」作 query 全文召回

```bash
python3 scripts/dkag_search.py "[目标范文完整标题]" --full --output ref_full_<任务>.json
```

- query 就用**目标那篇范文的完整标题**（标题越精确、目标篇越靠前）。
- 必须加 `--full`，**不得加 `--clean`**（`--clean` 会丢弃"全文"字段）。
- `--full` 会返回**全部命中篇**的全文（实测同一标题 20 篇、合计约 5.3 万字），因此该结果**只作本次提取的输入，不作为参考范文留存**——参考范文只保留目标那一篇（见步骤3）。

**`--full` 的覆盖边界（2026-09-29 实测补充，执行前先读）**：`--full` 只是在**可信搜索命中集内**附加 `return_full_content=True` 返回全文，**它不扩大召回集**。可信搜索的索引以**国家级站点**为主（gov.cn、moj.gov.cn、ndrc.gov.cn、court.gov.cn、creditchina.gov.cn、npc.gov.cn 等），对**地方人大公报、地方政府公报类站点覆盖有限**。上海实测：目标范文《关于本市贯彻实施〈上海市优化营商环境条例〉情况的报告》（来源上海人大 shrD.gov.cn）以**完整标题**作 query 调 `--full`，命中集 31 篇里 **0 篇来自该站**（域名全是国家级站点）；而**同一篇在深度搜索结果里是可召回的**（3 段 / 2349 字）。**即：地方公文类范文很可能取不到全文，这是接口覆盖问题，不是标题没写对。**

因此出现下列任一情况，**直接按"无参考范文"继续写作，不要换 query 反复重试**：

- `extract_reference.py` 返回 `ok: false`（若含 `similar_but_excluded`，那些是标题相近但**文种不同**的候选，不得当作范文）；
- 目标篇未出现在 `--list` 的候选里。

可以回看**本地已召回材料**辅助判断：若素材分类时已在召回结果里看到同文种成文（说明"这篇存在"），而 `--full` 取不回全文，即属本边界，照常写作，并在素材分类的"写法参考"里如实写明"未取到参考范文全文"。

**不要重试、不要换 query 再试**（2026-09-29 用户决策）：`--full` 不扩大召回集，换 query 也改变不了命中范围，重试只是白耗额度——**能搜到就用，搜不到就跳过**。

### 步骤3：提取目标篇全文并单篇落盘（用脚本，不要手写提取）

```bash
# ① 先列出候选题，确认目标篇标题（返回顺序即优先级）
python3 scripts/extract_reference.py official-docs/search-results/ref_full_<任务>.json --list

# ② 提取目标篇——按返回顺序逐篇比对标题，命中第一篇即取，只落这一篇
python3 scripts/extract_reference.py official-docs/search-results/ref_full_<任务>.json \
    --title "<目标范文完整标题>" --task "<任务名>"
```

脚本行为（与"先看第一篇是不是要找的、不是再看下一篇"一致）：

- 按返回顺序**逐篇比对标题**，**命中第一篇即取**，后面的不再看；
- 匹配方式：`exact`（标题完全一致，首选）→ `normalized`（去空白/发文机关前缀/公文缀词后一致，如"关于印发《X办法》的通知"对上"深圳市XX局关于印发《X办法》的通知"）→ `contains`（一方包含另一方，最宽松兜底）；返回 JSON 的 `match` 字段如实标注，**非 `exact` 时须自行确认命中的确为目标篇**；
- 只把**目标那一篇**的全文写入 `official-docs/input/参考范文_<任务>.md`（含标题、来源、日期、原文链接、字数 + 正文）；
- 匹配失败或无全文时返回 `ok:false` 并列出候选标题，此时如实告知用户，回到步骤1 重新选择或跳过。

### 步骤4：确认提取成功后告知用户

```
【参考范文已获取】

《文章标题》
来源：XX，日期
字数：约XXXX字
已提取全文，将在撰写时作为参考范文使用。
```

**落盘纪律**：本地保存的参考范文**只有目标那一篇**；`--full` 的全量返回（含全部命中篇）仅作提取输入，**不得作为参考范文留存或写入交付物**。参考范文只学结构与表达、不照搬内容，**不进入溯源核验报告**。

## 五、两阶段检索执行流程（纯脚本通道，3.7.5 起不再走 MCP）

搜索方案确认后，按**两阶段**执行（3.7.5 起，多路仍按并行规则；统一走脚本，需 API Key——MCP「深知可信工作台」大结果落盘方案改造完成后另行加回）：

**阶段一·首轮深度搜索（3 路按素材类型）**

1. 每路调用 `python3 scripts/deep_query.py "<query>" --area <地域> --json-only --output deep_<路名>.json`（需 API Key）。参数：`query`（按 Query 生成原则，**对象+关注方向，不限定到具体文件名/文号**）、`--area`（默认单地域；多地比较场景可逗号分隔传多地域，服务端自动拆子查询）。完整返回 JSON 由脚本**直接落盘**到 `official-docs/search-results/deep_<路名>.json`，脚本随后自动 `json.load` 校验；解析出 0 篇或 JSON 非法会直接报错退出。
2. **每路返回后，立即单独落盘并校验**：完整返回 JSON 原样保存在 `official-docs/search-results/deep_<路名>.json`，随后立即用 Python `json.load` 校验合法性。**未落盘校验通过前，不得发起下一路**；**不得"先把结果攒在对话里、等整批完成后统一落盘"**——宿主对工具结果有清理机制，延迟落盘的结果会"过期"无法读取，路数越多、越依赖"先攒后写"，越容易整批拿不到结果。
3. 运行转换：

```bash
python3 scripts/deep_convert.py official-docs/search-results/deep_<路名>.json --area 地域 --purpose "该路搜索目的"
```

4. 转换产物（`result_deep_<路名>.json`）与脚本通道 `--clean` 输出**同构**（顶层 `articles`/`total_articles`/`total_paragraphs`/`search_meta`，段落带自增 `id`）；**含快照/段落标题/发布日期可信度**，**缺独立"文号"字段**（文号在段落内容中）。脚本解析出 0 篇材料会直接报错退出（不会写入空结果）。

**阶段二·可信搜索补搜（缺口驱动）**

5. 深度搜索返回**含快照/段落标题/发布日期可信度**（`deep_convert.py` 已保留），但**缺独立"文号"字段**（政策文号在段落内容中）——**政策依据型必补搜**（补搜产出 policyFiles，正文引用政策文号靠其匹配）；数据/案例按研究资料口径表缺口（未给出/未确认/多口径未裁决）决定是否补搜。
6. 补搜调用 `python3 scripts/dkag_search.py "<query>" --area <地域> --time <时间> --purpose "<搜索目的>" --clean --output result_<路名>.json`（参数见 SKILL.md 搜索命令节；`segmentCount=2`、`simplified=false` 固定）。返回**立即完整落盘**到 `official-docs/search-results/` 并 `json.load` 校验。
7. **合并**：阶段一深度产物与阶段二补搜产物用 `merge_search_results.py` 合并后进入素材分类；两阶段产物都纳入溯源核验报告材料面板（深度产物缺独立文号的，政策依据型由补搜的 policyFiles 匹配补上）。

**两阶段共同约束**：

- 调用失败（Unauthorized/超时/超限等）时，**先串行重试该路一次**——并发多路时的鉴权失败多为 token 竞争瞬态错误，串行重试大概率成功。
- **深度搜索失败回退（3.7.5 修复）**：阶段一某一路深度搜索失败（接口报错/超时/返回 0 篇/JSON 非法，串行重试一次仍失败）时，**仅该路回退用 `dkag_search.py` 可信搜索重搜该路素材类型**，其他路不受影响、不整批回退；回退产物与该路未回退产物一并合并进素材分类。所有路都失败才如实告知用户并暂停等待确认；不得擅自改用 Web 搜索或跳过检索。
- **长文与精读口径**：召回段落固定 `segmentCount=2`（每篇最多 2 个相关段落），**不含全文**。政策依据的条款精读、事实核对以召回段落为准；**不得为"补全政策全文"对整批结果跑 `--full`**。**唯一的 `--full` 用途是参考范文召回**：当某篇召回文章与用户要写的材料高度相似、对其结构或论述逻辑有明显参考价值时，按第四节"参考范文召回流程"取该篇全文作参考——它与范文大纲接口并存、互不替代（大纲给结构建议，参考范文给同类成文的实际写法）。未走参考范文流程而段落不足时，如实告知用户该篇未能获取全文，不得凭印象补写。
- **通道唯一**：检索统一走脚本通道（`deep_query.py` / `dkag_search.py`），不得混用其他工具；返回落盘按第 2/6 步校验规则执行，不得以落盘麻烦为由绕道。

范文大纲同理：统一调用 `scripts/outline_reference.py`（需 API Key，3.7.5 起不再用 `doc_outline` 工具）。返回结构与脚本一致，直接进入大纲确认流程。

## 六、写法参考兜底：文风体例参考（webSearch）

**定位**：本路是**参考范文召回的兜底**——素材分类时未在已召回官方成文中发现同类范文（第二节"写法参考"判断为"无"），才用本路从全网搜同类文种的结构写法，弥补官方库确无同类成文的情况。**官方库有同类成文时优先走参考范文召回（第四节），不重复开本路。**

本路经用户确认后执行；写作中途需要补开时按补搜规则处理。

兜底时向用户说明（示例，不展示任何脚本参数）：

```text
写法参考说明：
已在本次检索素材中检查，未发现与这份材料高度相似的官方成文范文。
建议补充一路写法参考：从全网检索同类文种的结构写法（如"XX类公文 范文 结构写法"），
仅用于学习结构安排与行文表述，不作为政策依据或数据来源（来源多为非官方公开材料）。
是否执行？
```

内部执行（不向用户展示）：

```bash
python3 scripts/dkag_search.py "检索词" --area 地域 --search-channel webSearch --clean --output result_webref.json
```

使用纪律（详见 `reference/search_policy.md` 自由搜索边界）：

- 只学"怎么写"（结构、句式、过渡语），不搬"写了什么"：其中的人名、职务、机构、数字、政策条款一律不得进入正文事实层。
- 政策依据、数据信息禁用本通道；非官方页面上的转载数据不得使用。
- 使用前按"数据源 / 源网址域名"判别来源性质并显式标注；与本地 `standards/` 文种标准冲突时一律以本地标准为准（范文站常见过期国标与错误格式细节）。
- 范文站内容良莠不齐（AI 生成、拼凑、错字多），只取结构思路，不逐句模仿用语。
- 自由搜索素材不进入溯源核验报告（不占正文角标、不写入 materials 与 recalled_materials），也不生成知识专库链接；交付说明中如提及，仅表述为"文风参考材料"。

## 八、溯源核验报告 HTML

执行过搜索时，正式公文 Word 不在正文中添加来源角标、素材清单和知识专库链接。撰写完成后，单独生成 `标题_溯源核验报告.html`：报告打开第一屏即展示核验报告单（依据溯源、引用对应、材料新旧、材料构成、交付前检查五项指标，文案为自然说法），正文按章节分卡片展示并把 `[1]`/`【1】`角标变成可点击的来源跳转；右栏为来源文章面板：每张来源文章展示接口返回的原文标题链（如"标题：一、重点支持方向 › 方向2…"，即该段在原文件中的章节位置）、摘录块上方标注"▍ 原文原段（非 AI 生成）"、发布日期可信度为"高"的来源文章加"高可信"徽标、超 4 行摘录折叠并显示"展开全文"；多路检索时面板顶部按搜索条件生成筛选胶囊（单选 + 全部，另有"未引用"一项）；接口召回但正文未采用的相关来源文章进入"未引用素材"分组（不占正文角标编号，标"可查看原文"而非"已核验"）；移动端点正文角标弹出"正文表述 ↔ 原文原段"上下对照弹层。报告固定为 HTML，不生成 Word 版。

生成方式：

1. 先将核验报告整理为结构化 JSON，保存到 `official-docs/input/标题_溯源核验报告.json`，其中正文写入 `document_content`，正文引用使用 `[1]`、`[2]` 等角标——这是硬性要求：materials 非空时正文必须带角标并一一对应，`source_note_html.py` 校验到正文无角标会拒绝生成并报错，须修正 JSON 后重跑。JSON 必须用 Python `json.dump`（`ensure_ascii=False`）生成或用程序校验后再落盘，**禁止手工拼接**——正文与摘录里的中文引号（如 `"十四五"`）会直接破坏手拼 JSON 的合法性。
2. 再调用 `scripts/source_note_html.py` 生成 HTML：

```bash
python3 scripts/source_note_html.py official-docs/input/标题_溯源核验报告.json --output 标题_溯源核验报告.html
```

未指定目录的 `--output` 会保存到 `official-docs/output/`。也可以显式写为：

```bash
python3 scripts/source_note_html.py official-docs/input/标题_溯源核验报告.json --output official-docs/output/标题_溯源核验报告.html
```

生成边界：

- 必须使用 `scripts/source_note_html.py` 生成最终 HTML；模型只负责准备结构化 JSON，不得手写完整 HTML 页面。
- 不得自行拼接 `<a>`、`onclick`、按钮、卡片、CSS 或整页 HTML；不得用 Markdown、Word 排版脚本、浏览器保存网页等方式替代。

格式要求：
- 正式公文正文中不得包含 `【素材使用情况】`、`【知识专库链接】`、知识专库 URL 或素材清单。
- 溯源核验报告 HTML 是辅助核验文件，不是正式公文附件，不附在正式正文后；它包含核验报告单、完整正文和可点击溯源交互。
- 报告不再包含知识专库链接区：未引用召回材料已全量进入材料面板，完整召回在报告中即可回看；JSON 中无需 `knowledge_bases` 字段（残留该字段会被忽略）。
- `self_check` 为必填字段：把成稿快速自检的 5 项结果（`fact_basis` 事实有据 / `structure` 结构完整 / `placeholders` 无占位残留 / `ai_flavor` 无 AI 味 / `format` 格式合规）如实写入，通过写 `"pass"`，未通过写 `"fail: 原因"`；不得省略，也不得未检查就填 `pass`——核验单展示的就是这 5 项，如实填写是报告可信的前提。**只允许这五个键**：核对说明、待办、补充计划等不得写成额外键（如"备注""待核验"），也不得塞进值里替代"通过/未通过"——渲染层会忽略额外键，值应显式以"通过"或"未通过"开头。自检发现未闭环项应先补搜闭环，补不到才停下与用户确认，不得带缺口直接生成报告。
- `materials[].type` 使用四分类取值：`政策依据型` / `数据支撑型` / `参考案例型` / `表述参考型`，报告按类型分色展示并支持筛选；类型缺失时来源文章降级为灰色"材料"。
- `materials` 中每条素材至少包含 `material_name`、`source`、`section`、`support`；来自深知可信搜索的材料还必须把原始结果的 `源网址` 原样写入 `source_url`，不得依赖规范化标题反查。接口未返回原网址时不填、不猜测。存在数据口径、发布日期、文号或强判断时，应补充 `verification`，并使用“已完成……核验”口径，不得写“建议核对”“需人工核验”“以官方最新口径为准”等削弱可信度的措辞。
- `materials[]` 与 `recalled_materials[]` 每条必须带 `snapshot_url`（可选，接口 screenShotPath 快照链接，原文链接失效时的存档回看）、`search_key`（该材料来自哪一次搜索的阅读友好名，如“北京·养老政策”；同一次搜索的材料用同一个 key）。多路检索时报告据此在材料面板生成检索筛选胶囊，单路检索时自动隐藏。
- 政策类材料必须从同响应的 `policyFiles` 核对文号并写入 `doc_number`：所选材料对应条目的 `writtenText` 为空时，从**同文件的其他标题变体条目**回填（"联合印发…"/"关于印发…的通知"等变体，文件名主体相同即同一文件，模型认变体），仍无则不写；不得猜测文号。检索库对同一文件常有多个抓取条目，文号挂在发文版条目上，逐条精确匹配会漏（2026-09-20 机器人实测：27 条材料文号全空即此因）。**`doc_number` 只允许标准文号格式（如 `医保发〔2026〕12号`，含"〔年份〕序号"）**——禁止写"中办、国办印发""XX配套实施"等描述性文字充当文号（渲染层对非标准格式不显示，2026-09-21 长护险实测 47 条全因此不显示）。
- `snapshot_url` 与 `段落` 从搜索结果（脚本通道 `--clean` 同构产物，字段名 `快照链接`/`段落`）**对应材料原样复制**，不得整理时丢弃——快照是原文失效时的存档回看，段落是标题链与摘录比对的数据源。
- 整理 JSON 时必须把接口返回的 `段落`（含每段 `标题` 与 `内容`）和 `发布日期可信度` 字段**原样保留**到对应素材：段落标题用于来源文章的“标题：…”原文位置链（标注该段在原文件中的章节位置），可信度为“高”时来源文章展示“高可信”徽标。丢弃这些字段会导致报告缺失标题链与质量标识，属整理失误。
- `recalled_materials` 放接口召回但正文未采用的相关材料：排除明显无关的文章后**全量放入**，不做人工精选——供用户检查“没采纳的有没有更好”。结构与 `materials` 相同（含 `search_key`、`段落`、`source_url`）。未引用材料缺 `source_url` 时照实不填，报告在其卡片标注“待补链接”；“依据溯源”与“已核验”只统计正文引用的材料，未引用材料不影响核验结论。
- 核验单中的"依据溯源""引用对应"由脚本按 JSON 与正文自动计算：素材缺 `source_url` 或摘录、正文角标无对应素材时，核验单会如实显示待补与未绑定，因此整理 JSON 时必须保证素材与角标一一对应。
- 每条素材只写实际用于正文的核心依据，不机械罗列所有搜索结果；同类材料可合并说明，避免来源说明变成流水账。
- 不得使用表格承载素材使用情况；HTML 由脚本生成卡片式布局。
- 不得使用 `→ 用于：`、箭头符号或其他内部工作流标记。
- 写作素材和参考范文分开列出。
- 参考范文只写 `参考用途：` 和 `使用边界：`，不得把表述参考混入写作依据。
- HTML 由 `scripts/source_note_html.py` 生成；不要手写完整 HTML 页面，也不要用 Word 排版脚本生成溯源核验报告。
