# AI 算力与技术服务材料 - 格式标准

## 一、文体分类
- **类型**：工作材料（技术论证类）
- **行文方向**：项目主体→决策/采购/审查单位
- **红头格式**：通常无需红头，可作为请示附件
- **发文字号格式**：一般无文号

## 二、适用场景
AI 算力服务、GPU/服务器租赁、模型服务、智算中心、云端/本地部署比较、技术服务需求等专项材料。通用公文、普通采购、费用申请和办公设备申请不默认进入本文件。

## 三、格式规范

### 3.1 标题
- **字体**：方正小标宋简体，二号
- **格式**：`[事项]算力服务采购方案` / `[事项]技术需求书`
- **示例**：
  - `XX单位AI算力服务采购方案`
  - `XX项目GPU服务器租赁技术需求书`

### 3.2 正文结构

#### 字体字号
| 内容 | 字体 | 字号 | 缩进 | 行距 |
|-----|------|------|------|------|
| 正文 | 仿宋_GB2312 | 三号(16pt) | 首行缩进2字符 | 固定值28磅 |

**基本结构**（采购/租赁）：采购目的 → 服务范围 → 资源规模和性能要求 → 服务期限和交付 → 部署/调度/运维/升级 → 价格结构 → 验收、SLA、故障响应 → 安全、数据、保密和审计

**基本结构**（可研）：项目背景和结论 → 业务需求和资源/Token 测算 → 现有使用和未来增长 → 技术路线和模式 → 费用测算和路径比较 → 服务能力、SLA、并发和运维 → 预期效益 → 数据安全合规 → 实施和验收

## 四、注意事项
- 算力需求从业务场景写起，再落到资源指标；把技术单位转化为成本、服务能力和风险边界。
- 不写"先进算力""强大平台"等无指标判断；使用时应紧跟可核验指标。
- 成本比较基于同一服务期限和需求假设；写明在哪个规模、期限、口径和假设下更可控。
- 技术条款要可度量可检查（GPU 数量、存储、带宽、SLA、并发、验收内容）。
- 区分实际数据和估算数据；使用深知搜索时，政策、行业数据、案例用于支撑论证。
