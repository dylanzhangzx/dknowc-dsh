# 文种写法要点（按用途组织）

本文件补充 `standards/*.md` 的格式标准，只回答“这类材料怎么写、哪些不要补”。格式、字体、版式仍按对应文种标准；事实边界、篇幅、标点、表格和交付按 `writing_rules.md` 与 `fact_discipline.md`。

使用方式：动笔前按文种读对应一节；文种不在下表时，按最接近的类别处理，并回到对应格式标准。每节只列写法要点，不替代格式标准中的标题、主送、落款和字体要求。

## 一、报告 / 情况报告

- 先确定读者这次要掌握的问题，再按问题组织；同一问题的事实、已有处置、未结状态放在一起。
- 背景和过程只保留能解释问题或支撑判断的内容，不按材料数量平均铺陈，不另立无关的同期工作栏目。
- 子集进度只归该子集，不套给整组；数量合计不能代替逐项状态核对。
- 建议保持建议或拟议状态，不写成已经决定；原因分析说明判断程度，不写成已查明的结论。
- 业务日期、统计截止时点、落款日期分开，不把落款日期当作最新进度。
- 结尾完成报告动作；不把情况报告写成调研报告、方案或请示。

## 二、通知

- 骨架：事项或目的 → 对象 → 办理内容、材料和要求 → 时限、渠道、联系人 → 结尾语。
- 只写材料给出的办理要求；不替对象增加责任、时限、整改动作或后续安排。
- 参会对象、主送范围和称谓沿用材料原称谓，不自行扩大或缩小。
- 附有方案、制度或其他文件时，通知交代印发、执行或报送要求，附件保持自己的结构和名称。
- 结尾语按材料取舍，不为了显得完整新增办理承诺。
- 短通知直接说清事项，不强行分节；长通知按办理环节分段。

## 三、请示 / 申请

- 一文一事；缘由、依据和当前条件共同支撑本次请求，短稿可以一两段写清。
- 骨架：请示缘由 → 请示事项/所需资源 → 请批语；请批语通常在文末、落款前单独成段（模板另有要求除外）。
- 不把已有金额、既有项目或日常经费改写成新的请批事项；材料没有提出追加请求时，不自行增加。
- 不另造检查来源、使用频次、投诉记录来证明必要性；常识支持的一般作用可以分析，不写成已经反复发生。
- 主送、落款、模板字段按材料使用；缺项按事实克制规则处理，不留无用途占位。
- 请示用于请求指示或批准；申请保留原因、依据、事项和当前状态，文种按实际用途判断。

## 四、函 / 复函

- 先确认来函事项、发函对象和答复范围；复函逐项回应，不答非所问。
- 无意见复函简洁明确；有意见复函写清“原则同意”“不同意”或“建议修改”，并落到具体条款。
- 不替来函单位补充其未提出的事项；不把征求意见稿写成已经生效的文件。
- 涉及多部门职责时，按材料写清分工，不自行分配责任或会签顺序。
- 结尾语按函种使用（此函、特此函复、请研采等）；模板已有结尾的照录。
- 平行文语气平等克制，不用命令式表述；上行、下行关系按实际行文方向处理。

## 五、工作总结

- 用代表性事实说明做了什么、做到哪一步、有什么作用；同类细节概括共性，不按材料数量平均分配篇幅。
- 成效判断与证据匹配：系统部署、数据整理或流程衔接完成，只证明相应事项完成；运行稳定、效率改善等判断需要运行、测评或反馈支撑。
- 问题、原因、经验和下一步随相关工作衔接，不另立空泛章节；短总结可以自然成篇，不强行凑“成绩—问题—下一步”三段。
- 下一步与已有问题、数据和工作基础衔接；具体主体、程序、时限、数量和承诺按材料或授权范围表述。
- 结尾归纳前文工作、问题、经验和安排，不换词重复全文，不用口号收尾。
- 不把一次做法概括成普遍有效的规律；不把拟议、待评估的事项写成已经确定。

## 六、讲话稿 / 致辞

- 先确定场合、发言身份、听众和发言目的，再决定内容、详略和语气。
- 骨架：场合与身份 → 主题态度 → 已有事实、观点或工作基础 → 重点任务、体会或期望 → 与场合相称的收束。
- 判断和要求由材料事实和直接分析支撑；不用排比、口号、宏大叙述代替内容。
- 材料只给主题、工作考虑或下一步方向时，讲清目的、意义和衔接；不为篇幅补写成效、受众、职责或部署。
- 称呼、受众和称谓沿用材料或用户要求；开场和结尾按场合需要，不套固定模板。
- 内部讲话保留内部表述；公开发布时按公开口径核对，不把内部判断直接改成公开承诺。

## 七、实施方案

- 先定要解决什么问题、达到什么状态、谁执行、何时完成，再写任务和保障。
- 骨架：总体要求/目标 → 重点任务 → 责任分工 → 时间安排 → 保障措施；短方案可以合并相邻章节。
- 任务写清动作、对象、抓手和结果，不写“加强领导、提高认识、强化协同”一类空泛措施。
- 责任主体、时限和验收方式按材料；材料未给时写到足以执行的粒度，不伪装成已经批准的具体分工或节点。
- 不把预期效果写成已有成效；不补材料没有的预算、编制、系统名称、考核机制。
- 任务数量按实际事项决定，不为了结构完整强行凑三项或五段。

## 八、整改方案

- 先锁定问题来源、对象和当前状态（已完成、正在整改、尚未启动、等待复核）；形成方案不等于完成整改。
- 每个问题写清：纠正什么、怎样避免重复、由谁检查、何时完成；同源问题可以合并治理。
- 原因分析服务于措施选择；判断程度与依据相称，不归定个人动机，不把记录漏项断定为既有流程缺失。
- 不机械重复“加强学习、完善制度、强化监督”；措施要能对应具体问题，避免一份措施套所有问题。
- 建台账、开会、发文件、开展培训本身不等于整改完成；验收看问题是否纠正、目标是否达到、证据是否可核。
- 预期效果用“有助于”“降低”“避免”“推动”等条件表达，不把风险写成已经发生的损失。

## 九、会议纪要

- 骨架：会议主题和范围 → 议题或讨论要点 → 议定事项 → 责任单位/责任人 → 完成期限 → 未决事项。
- 只记录实际形成的决定；不补“会议认为”“会议强调”“达成共识”等材料没有的结论。
- 发言人的建议、判断和条件保持归属；发言顺序不作为结论顺序。
- 责任和期限按记录绑定；未形成结论的内容保持待议或未决状态。
- 会议类型帮助选择表达重点，不替代记录内容；只有议题、责任和期限时，就围绕这些内容成文。
- 纪要要可执行：事项、责任、时限和反馈渠道清楚，避免只写讨论过程。

## 十、调研报告

- 骨架：对象与范围 → 方法、样本和资料来源 → 主要发现与问题 → 原因或影响 → 建议、待定事项或结论。
- 方法与样本写清楚；材料未给就如实省略，不补“代表性样本”“广泛调研”“深入走访”等无据表述。
- 调研方法只写本轮实际执行的方法；没有内部材料、没有实际座谈/走访/台账查阅时，只写公开检索和资料比对，不补写未发生的调研过程。
- 附录承诺必须兑现：写了附录一/二/三/四，就要有对应内容；没有附录就写“数据边界说明”，不设空的填报表。
- 镇级或本单位数据未公开时，正文直接写数据边界和需以台账为准的指标，不用不存在的附录兜底。
- 实际数据、样本观察、访谈原话和分析判断分开写；不把分析判断写成已核实事实。
- 有限样本不外推：几个乡镇、几家企业的做法，不写成“全县普遍”“全省领先”；结论范围随样本范围收窄。
- 建议对应前文发现；不补代表性论证、成本测算、实施方案或已经生效的政策决定。
- 使用中性、可复核的分析语气；上行报送保留“汇报情况、供决策参考”的口吻，公开发布不改写成命令、政策或已经生效的决定。
- 格式和结构细节按 `standards/29_research.md`。

## 其他文种

- **可行性研究**：按 `standards/30_feasibility.md`；主体是研究判断及成立条件，需求、方案比较、投资和实施条件支撑判断，短篇初步可研可用自然段，不强套固定章节。
- **宣传材料**：按 `standards/23_publicity.md`；先明确面向谁、宣传什么、受众要了解或采取什么行动，再按理解顺序写内容、方法和渠道。
- **制度/办法**：按 `standards/28_rules.md`；条款写清适用对象、职责、程序、责任和施行时间，不补材料没有的罚则或审批环节。
- **通报/公告/通告**：按对应标准；事实、范围、执行要求和时间写清楚，不扩写材料未给定的责任和后果。

## 通用写法自检

动笔前和定稿前各过一遍：

1. 读者这次要了解什么、判断什么、办理什么？
2. 哪些是事实、哪些是分析、哪些是建议？三者是否分开？
3. 哪些内容是材料给的，哪些是我补的？补的内容是否有依据？
4. 有没有为了篇幅、结构或“显得完整”补写背景、表态、责任、时限或口号？
5. 格式、标题、主送、落款和字体是否按对应文种标准执行？
