# 异常处置（troubleshooting）

## 检索侧

| 症状 | 原因 | 处置 |
|---|---|---|
| 带标签返回 0 条 | 标签过滤波动（非确定性）；或该文件不带此标签 | 如实记录 `label_zero`；原参数重试一次；仍 0 → 另发无标签独立检索，两次分别落盘；答案写"本次未召回" |
| 同一查询前后结果不同 | V2 召回非确定（2026-11-05 实测 6→0→6；2026-11-06 复现 0→5） | 多次结果都落盘；结论基于材料而非单次结果；不断言"库里没有" |
| 返回"502 Bad Gateway"等异常标题 | 抓取失败页入库（带税务标签，稳定出现） | 如实展示来源；不引用其内容；记入问题清单 |
| 镜像副本缺文号（约 32%） | 多镜像抓取元数据不全 | 引用降级（标题+日期+源网址）或换带文号副本；需要时 `--file` 核对 |
| 同一政策多个年度口径同屏 | 年度混排（测试实测单次最多 8 个年份） | query 加年份词；引用按文号+日期锁定；答案写适用年度 |
| 想查的文件被标签排除 | 主主题不在所传族（如社保文件不在税务族） | 切换标签族重查（见 tags.md 决策树）；两次结果都保留 |
| `service_area` 传了但结果不限该地 | 地域参数行为不稳 | 核对每篇的发布机构/办理地域；不放心就按标题/机构本地过滤 |
| 语义检索查不到某份文件 | V2 对"文号+年份+地方"召回弱 | 先用 `--file "文件全名"` 走 001 全文兜底确认；找不到或只命中旧版才联网 |
| `--file` 报下载失败（如仅允许 https / 地址不可达） | 下载接口返回的地址不可用（接口问题） | 如实报错、不换地址绕行；答案注明"全文下载暂不可用，以下依据来自条款级检索"，并把下载地址问题记入接口问题清单 |
| 库内只有旧年版、问题问最新年度 | 版本敏感 | 旧版不能当现行；联网核新文，研究资料写明"库内为 X 版、外部为新版" |
| 阶段二联网返回 0 条/全是无关页 | 联网索引覆盖问题或 query 太窄 | 换更贴近用户原话的 query 重试一次；仍无则进入阶段三（宿主有 WebSearch 时），否则如实说明"公开网络检索不可用，以下结论待核验" |
| 阶段二返回结果带很多网页模板文字 | 接口不做模板清洗 | 引用前剥离导航/客服电话/面包屑；只引正文段落 |
| 宿主无 WebSearch 工具 | 宿主能力限制 | 停在阶段二并如实说明；**不得伪造外部材料**，不得用模型记忆冒充检索结果 |
| 外部材料与库内材料同 URL | 双通道重复 | merge 已按标题+URL 去重；保留官方材料卡，外部段落与元数据不进官方卡 |

## 数据侧（只记录，不迁就）

| 症状 | 处置 |
|---|---|
| `validityStatus` 与实际不符（现行标失效等） | 不拿状态字段下结论；用文号、发布机关、正文废止/延续条款核对；异常记问题清单 |
| 版本链串档（查 A 返回 B 的版本） | 版本信息仅参考；按标题精确匹配取正文 |
| 同一文件多副本标签不一致 | 记录各副本标签；需要时按标题/文号二次检索；不下"该文件不属于税务"的结论 |
| 商业库镜像（威科等）/源网址为空 | 如实展示数据源；有官方源并列；不写"官方原文" |

## 能力层校验（verify_claims）

| 症状 | 原因 | 处置 |
|---|---|---|
| `direct.quote 在来源 span 中找不到` | 引文被改写、合并了多段，或用了新闻转述 | 回到材料原段逐字复制；省略号只用于确实省略的中间段 |
| `count 声称 N 项，引文数出 M 项` | 把"（一）（二）"合并成一句，或数错枚举 | 引文保留完整枚举标记，count 与标记数一致 |
| `claim 税种与问题税种不一致` | claim 挂错税种（如增值税结论挂到企业所得税问题） | 按问题画像改 claim.tax_types，或拆分 claim |
| `days/amount/tax 台账=…，工具=…` | 心算、口径或四舍五入不一致 | 用 `calc_tax.py` 重跑，把工具输出原样写回 claim |
| `negative 缺少 coverage` / `wording` | 只写"没找到" | 写清检索覆盖与"截至YYYY-MM-DD，公开渠道未见……" |
| `次级媒体 external 缺少 official_value 或待核验措辞` | 把媒体报道当官方口径 | 补官方公开口径，或明确写"待核验/未见正式文件" |
| `答案强断言没有 claim 锚点/引用` | 正文写了结论但没落 claim/角标 | 给该句挂 `[n]` 或写入对应 claim 的 `answer_anchor` |
| `--out/--run 不能指向 Skill 安装目录内` | 把输出写回安装目录 | 换会话工作区的运行目录，如 `./runs/<任务>-<时间>`；Skill 目录只读 |
| `--out 目录已有运行结果` | 想复用旧目录跑新任务 | 新建独立 run；续跑/补查用 `--run`，不要复用已有 run |
| `--output 文件已存在，不覆盖已有产物` | 同一 run 重跑同名产物 | 换文件名（如 `_v2`）或新建 run；报告同题重跑会自动 `_v2` 另存 |
| 渲染报错「核验未通过，未生成报告」 | 结构轨或 AI 验收轨任一不过 | 按 stderr 列出的原因逐条修正（补角标/补摘录/重跑 verify/补 selfCheck 证据）后重跑；不产出问题报告 |
| 渲染报错「核验记录与当前答案/证据不一致」 | 答案或材料在核验后被改动（trust_digest 摘要不匹配） | 重跑 `verify_claims.py` 生成新 `tax_verify.json` 再渲染；不允许沿用旧绿标 |
| 渲染报错「缺少核验记录」 | 没传 `--verify-file` 且运行目录无 tax_verify.json | 传运行目录内的 `tax_verify.json`；不要靠手写 selfcheck 顶替域内核验 |
| 「AI 验收有声明通过但无可回查证据的项」 | selfCheck 声明通过但 evidence 无要素 | 每项 evidence 补材料编号/条款号/文号/日期/标准号（见 answer-and-report.md 契约） |
| 渲染报错「只认通用 JSON / 请先用 build_report_input 转换」 | 直接把 merge 产物喂给渲染器 | 先 `build_report_input.py <merge> --run <run> --output input.json` 转换，再渲染 input.json |
| 渲染报错「必须用 --run 指定…」 | 没传 `--run` | 渲染/转换统一传 `--run <运行目录>`（相对产物落 run 内） |
| 「AI 验收有未通过项」 | selfCheck 某项 verdict=fail | 修正答案或补检索，把该项改为 pass 并附证据后重跑 |
| challenge 走了领题流程（输出带 question） | 注册通行码失效/停用，脚本已自动回落 | 按原领题流程答 `answer` 即可；输出 `keyFallback` 会标明原因 |
| challenge 返回 SMS_RATE_LIMIT / RESULT_UNKNOWN | 限频或发送结果未确认 | 停点：等用户明确要求或确认收到短信，不自动重发（回落等于再发一次） |
| `check_answer` 报「税率/征收率」 | 句子里有具体税率数字且同一行没有年度或文号；只写“税率档/税率表”不会报 | 给出 `13%`/`百分之十三`/`13个点` 时补 `2026年` 或文号；假设句无需改写 |
| 研究资料统计显示 0 项 | 内核 1.0.2 解析器只统计「事实/口径」关键词分节下的**表格行**（三级标题会重置分节，列表不计数） | 按 `## 核心事实总表` / `## 数据口径` 二级标题 + 扁平表格重写；表格直接放二级标题下，不用列表、不套三级小标题 |
| `initialize.py` 返回 `api_key_invalid` / `ready=false` | Key 格式合法但已失效（401/403） | 按开通引导重新获取 Key；不要用 `--no-verify-key` 绕过 |
| `initialize.py` 提示「已降级放行」 | 校验请求网络超时/5xx | 可继续，首次检索可能失败；联网后重跑 initialize |

## 工具侧

| 症状 | 处置 |
|---|---|
| Write 已存在文件失败（宿主要求先 Read） | 用短标识命名 `tax_<任务>_*`，不要固定文件名 |
| `check_answer.py ... | tail; echo $?` 永远 0 | 管道吞退出码；直接跑，必须截断用 `set -o pipefail` |
| 渲染报告引用块"未在材料中找到" | 段落裁剪丢段；材料很短别裁剪，必要时 `--no-trim-uncited` |
| 表格内角标渲染错位 | 表格角标用紧凑上标，或把依据放到表格下方"表内依据"行 |

## 升级路径

测试发现问题 → 改脚本/规则层 → 重跑验证；**不手改单份报告**。数据/接口问题 → 记入研究资料，由维护仓库的问题记录统一反馈（不入 skill 包），交付物只暴露现象不评价版本。
