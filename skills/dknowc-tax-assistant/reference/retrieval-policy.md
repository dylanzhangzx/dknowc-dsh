# 全文/版本兜底（retrieval-policy）

## 何时用

只在这些情况用，**不要默认每次下载全文**：

1. V2 召回的段落被截断，需要看条款完整上下文；
2. 需要核对文号/发布日期/签发机关，而 V2 返回的镜像副本缺文号（实测约 32% 副本无文号）；
3. 用户明确要文件全文或某几条的完整原文；
4. 需要判断政策延续/替代关系（新公告替代旧公告），要看文末废止条款。

## 调用

```bash
python3 scripts/tax_search.py \
  --file "财政部 税务总局关于增值税小规模纳税人减免增值税政策的公告" \
  --run ./runs/<任务>-<时间> --output tax_search_full.json
```

链路：政策条件筛选（按标题，全名→去"关于"前缀逐步放宽）→ 本地按标题匹配度+状态+日期挑副本 → 历次版本（尽力，失败不阻断）→ 政策正文 → 全文下载。**不做法条切分**——税务没有"按第X条切"的核心诉求，直接返回全文（超 6 万字截断并如实标注）。

## 副本挑选规则（脚本内置）

- 标题与查询名完全一致 > 前缀一致 > 包含；
- 剩余部分含"征求意见稿/草案/解读/问答/培训"等噪音词的副本剔除；
- `EXPIRED_OR_REPEALED` 降权但不一票否决（库内效力状态有错标先例，不作结论依据）；
- 同分下取成文日期新、正文长的。

## 已知坑（沿自深知系列产品实测，税务同样适用）

| 坑 | 处置 |
|---|---|
| 效力状态错标（现行标失效、废止标现行） | 不直接拿 `validityStatus` 下结论；用发布机关、文号、正文里的废止/延续条款核对 |
| 版本链串档（查 A 文件返回 B 文件版本） | 版本信息只作参考；正文以标题精确匹配的副本为准 |
| `eff_time` 不按日期过滤 | 需要历史版本时看"历次版本 + 政策正文"，不传 eff_time |
| 全文含站点导航杂质 | 引用时只引条款部分；渲染前不裁剪导航也不影响核验（按段落引用） |
| 商业库镜像（如"威科"） | 如实展示数据源；有官方源链接时并列；不把商业库写成官方原文 |

## 全文引用规范

- 引用块逐字，标明"《文件全称》（文号，发布日期）第X条/第X项"；
- 全文段落里找不到的原话不引用；
- 截断文件（`_tax.truncated=true`）要在答案里注明"文件较长已截断，完整全文见源网址"。
