# 路径二：法条模式（兜底——仅在 V2 触发条件时使用）

法条模式 = 政策条件筛选（001）→ 历次版本（003）→ 政策正文（002）→ 全文下载（005）+ 本地按“第X条”切分。政策文件没有“第X条”（常见“一、二、（一）”）时，返回库内全文（`legal-policy-fulltext`），不报“未能切出目标条文”。

**日期口径**：002 的 `发布日期` 通常是本次修正/公布的成文日期（如劳动合同法 2012-12-28），`生效日期` 可能是法律原始施行日（如 2008-01-01），**不一定是本次修正的施行日**。本次修正的施行日看 003 的 `statedEffectiveDate`（如 2013-07-01）。报告写版本时分开写“修正公布日”和“修正施行日”，不要把 2012-12-28 写成“修正后施行日”。

## 什么时候用

只有以下情况才用本路径，并在研究资料里写明原因：

1. V2 两轮（带标签 / 不带标签）均为 0 条
2. 目标条号没召回，或段落不完整/没带条号
3. **版本敏感**：新旧法、废止法、时间效力——V2 无版本字段，必须取全文核对版本
4. 需要核对条文是否被截断

## 基本用法

```bash
python3 {baseDir}/scripts/legal_search.py \
  --law "中华人民共和国劳动合同法" \
  --article 47 \
  --output legal_labor_47.json
```

脚本内部：001 按标题定位 → 排除 `EXPIRED_OR_REPEALED` → 003 取最新修正日期 → 下载候选副本并校验正文标记 → 选定后 002/005 取全文 → 按“第X条”切分。

选本优先级（脚本内已实现，Agent 不要手工改）：标题精确匹配 > 成立日期等于最新修正日 > 正文含修正日标记 > 非正式文本词降权。

## 多条款模式（同一部法取多个条号）

```bash
python3 {baseDir}/scripts/legal_search.py \
  --law "中华人民共和国劳动合同法" \
  --articles 38,39,40,41,46,47,48,87 \
  --output legal_labor_multi.json
```

- 一部法只解析一次、只下载一次全文，切出多个条号；输出 1 篇材料 + 多个段落，角标统一用 `[1]`
- `_legal.articles` 是请求条号，`_legal.missing_articles` 是未切出的条号；有 missing 必须补搜或标“未检索到该条原文”
- 切条边界取“下一条标题”和“下一章/节/编标题”中较近者；章标题后的第一条按结构条标题处理，不当作行内引用；正文里“依照第X条”的行内引用不会切出独立段落
- 多部法分别跑，再用 `merge_search_results.py` 合并

## 跨期/新旧法：按基准日取当时版本

```bash
python3 {baseDir}/scripts/legal_search.py \
  --law "最高人民法院关于审理民间借贷案件适用法律若干问题的规定" \
  --article 第二十六条 \
  --reference-date 2020-01-01 \
  --output legal_lending_2015.json
```

- 传 `--reference-date` 后，脚本用 003 返回的 `inferredApplicableFrom/To` 选出基准日当天有效的版本，再用 002（`encryptedVersionId`）取该版全文
- 不传则取最新版；普通问题不要加这个参数
- 跨期问题取两段：旧段传合同成立日/行为发生日，新段传起诉日/今天，分别取条文再合并

## 多条法合并

```bash
python3 {baseDir}/scripts/merge_search_results.py \
  --run <run> \
  --input legal_labor.json \
  --input legal_labor_regulation.json \
  --search-key "劳动合同法" \
  --search-key "劳动合同法实施条例" \
  --output legal_merged.json
```

合并后每篇材料带 `编号`，答案角标用合并后的编号。`--search-key` 只传 1 个时会应用到全部输入。

## 司法解释、行政法规、地方性法规

- `--law` 可直接传司法解释全名
- 查不到时改用语义模式并把地域/文号写进 query
- 案例、裁判文书接口不保证覆盖；能检索到就作为参考材料并标注来源，不得把媒体报道当裁判依据

## 结果使用纪律

- `段落[].内容` 是原文；`版本状态`、`版本标记`、`版本标记命中`、`版本状态存疑`、`版本状态说明`、`选本依据` 是审计字段，只留在 JSON，不进正文和报告说明文字
- 交付物里唯一可写的中性事实是报告材料卡的“原文含最新修正日 YYYY-MM-DD”；没有就不写
- 版本状态、版本链的问题在 `troubleshooting.md` 记录，不改写查询掩盖
