# 异常记录与报错处理

## 一、原则

接口没兑现契约时：**如实记录、在报告中暴露，不改写查询去绕过去**。以下异常要写进研究资料，并在报告材料卡/核验单体现：

| 异常 | 记录方式 |
|---|---|
| 带标签返回 0 条 | 记 `label_zero=true`；如另跑无标签检索，两次分别落盘、报告分别展示 |
| 返回的 `文件标签` 不在目录 | 记目录外标签原文；报告材料卡保留接口返回 |
| 版本链条目与目标法不符 | 记录条目标题与日期；说明选本时如何排除 |
| 同一部法多副本标签不一致 | 记录各副本标签；报告中不据此下结论 |
| 效力状态与正文修正日矛盾 | 记录状态值与修正日；交付物中不写版本评价 |
| 全文含站点导航杂质 | 记录 fileId 与杂质片段；不作为条文引用 |

详细证据见项目内部问题清单（不随公开包分发）。

## 三、报错处理

- `api_key_missing`：走开通引导，不检索、不输出法律结论
- `quota_exhausted=true`：停止重试，引导到 `https://platform.dknowc.cn/auth/#/login` 查看积分
- `401/403`：Key 失效或无权限；按 `{baseDir}/reference/onboarding_scripts.md` 处理，不反复试
- 001 零候选：换法律全名/简称重试；仍无，走语义模式定位
- 政策文件没有“第X条”：001 已命中但正文是“一、二、（一）”结构时，法条模式返回库内全文（`legal-policy-fulltext`），不要报“未能切出目标条文”，也不要直接跳 WebSearch
- 库内只有旧版政策：问题含“最新/现行/年份”时，先用 WebSearch 核对是否有新版；报告写清库内版本日期与外部新版日期，不能拿旧版当现行
- 002/005 下载失败：先重试；仍失败则如实报告“正文接口获取失败，未完成核验”，不得写成“库内没有/未检索到全文”；接口恢复后重跑，不能用失败结果下“库内未收录”的结论
- 002/005 下载失败后换下一个候选副本；全部失败则如实报告“正文不可取”，不得用语义段落冒充法条原文
- 条号未切出：检查条号写法（阿拉伯/中文数字），换语义模式补搜；仍无则标“未检索到该条原文”

## 四、不要做的事

- 不要因为 V2 返回 0 条就静默去掉标签重查
- 不要因为版本链有噪音就在查询层改写法律名去规避
- 不要因为效力状态错标就在交付物里写版本评价
- 不要把异常当成正常结果继续写结论
