# 路由规则（routing）

深知可信PPT v1 只有一条顶层路线：**Generate 生成演示稿**。本文件负责入口判断与模式选择。

## 一、路由纪律

| 规则 | 行为 |
| --- | --- |
| 单一路线 | 所有「做 PPT / 演示文稿 / 汇报 / 课件」请求都进入 Generate 主线 |
| 匹配即执行 | 请求已明确匹配时直接执行，不得向用户罗列实现路径或让用户选流程 |
| 缺前置条件 | 说明缺什么并停止，不得发明替代方案（如缺 API Key 时不得改用外部搜索） |
| 一次一个判别问题 | 请求模糊时最多问一个判别问题，不连环追问 |
| 阻塞门必须停 | 每个确认门必须等用户显式确认；不得代用户决定、不得跨门捆绑工作 |

## 二、入口判断

本 skill 处理的请求形态：

- 从主题/需求生成 PPT（「做一份XX汇报PPT」「把XX做成演示文稿」）
- 从已有材料生成 PPT（用户提供 Word/PDF/Markdown/文本，要求转成 PPT）
- 修改/重做本 skill 已生成的项目（读取 `dknowc-projects/` 下原项目，按内容包变更后重新出 SVG）

不处理的请求（说明并停止，或引导到对应能力）：

- 纯公文写作（Word 交付）→ 不在本 skill，提示用户这是 PPT 专用 skill
- 只要文字大纲不要 PPT → 可给大纲，但说明本 skill 的交付物是 .pptx

## 三、Generate 内部模式选择

| 条件 | 模式 |
| --- | --- |
| 用户只给主题/场景，无素材 | **主题模式**：先设计检索方案，过「检索方案确认门」，深知检索补齐事实基线 |
| 用户给了材料（文档/文本） | **材料模式**：以用户材料为主体整理内容包；仅对影响结论的事实缺口按需补检索（补检索同样过确认门） |
| 用户给了材料且明确说「不用查，就用我给的」 | 材料模式免检索；可信溯源核验报告中素材标注「用户提供」 |

## 四、运行时权威

模式确定后，一切执行细节以 [`generate-pptx.md`](./generate-pptx.md) 为准。本文件只管入口判断，不得在执行阶段被重复引用。
