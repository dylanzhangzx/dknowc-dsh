# 深知素材使用规则（material_usage）

本文件约束深知可信搜索素材如何进入演示页面。核心原则：**素材服务于观点，全程可溯源**。

## 一、素材四分类与页面用途

| 类型 | 页面用途 | 呈现要求 |
| --- | --- | --- |
| 政策依据型 | 政策背景、条款解读、落实要求页 | 注明文件名与发文机关；文号/日期只有口径一致时才写 |
| 数据支撑型 | 图表页、指标页、成效页 | 图表数据 + 「数据来源：XXX」注释；口径与时间点写清 |
| 参考案例型 | 做法、经验、案例页 | 标注案例主体、地区、时间；不把个例泛化为普遍事实 |
| 表述参考型 | 仅吸收表达方式 | 不单独成页、不挂来源（无事实内容） |

## 二、进入页面的规则

1. **先观点后素材**：先定该页要表达的核心结论，再选支撑素材；不因「检索到了」就塞进页面。
2. **严禁跨层级引用**：外省政策不得作为本省政策依据；国家政策与地方细则不得混用口径。
3. **数字纪律**：精确数字、比例、金额、排名、全国首个/唯一等表述，只有内容包素材清单中能回溯到检索材料时才写；无法核实的改为概括表述或删除。
4. **时间纪律**：超出演示时间范围的信息只作背景/趋势，不当期成效。
5. **图表下必须标来源**：所有 chart/table 页加 13px 灰色「数据来源：XXX」注释行。
6. **PPT 页面不放角标**：页面保持版式干净（与公文正文同理）；可点击溯源由独立溯源核验报告承载。

## 三、溯源核验报告（双版）与答案文件编制规范

执行过检索的任务生成**两版报告**，同一脚本（`render_trace_html.py`）、同一形式与交互；输入均为「检索 JSON + 带角标的答案文件」。报告为**核验式**呈现（3.7.0 同源重构）：顶栏身份章 + 工具组（只看正文/复制全文/打印归档下拉）+ 阅读进度条；核验报告单（依据溯源/引用对应/材料新旧/材料构成/交付前检查五项指标）与过程回顾条（检索→入库→逐条比对→核验完成，数字全部真实计算）；正文为连续文档流（章节标题带「本章引用 N 处 · 已核验」徽章），句后**引文胶囊**（编号圆徽章+来源文章标题，点击原地展开溯源卡：原文直达区+文号·数据源·日期+多段分块摘录，再点收起；同一块内同一材料只保留最后一处角标与胶囊）；**知识专库**独立视图（大搜索、热词真实计算、检索分组 tabs、已引用/未引用筛选、单列宽卡）；来源文章卡含面包屑标题链（文章 › 章 › 节）、高可信徽标（发布日期可信度=高）、未引用灰标；接口返回的原文链接**原样进报告**（不做连通性检测、不隐藏，2026-10-08 起移除检测）；接口提供存档快照（screenShotPath）时作为**附加回看入口**与原文链接并存，按钮如实区分「查看全文/查看存档全文」；未绑定角标红色警示；`@media print` 打印归档（只打印正文 / 完整归档含来源文章附录）；报告界面术语对齐深知晓：集合视图＝**知识专库**、一篇召回文章＝**来源文章**（核验单五项指标名与素材四分类等规则术语不变）。

| 版本 | 生成时机 | 作用 | 答案文件内容 | 自检项（self_check） |
| --- | --- | --- | --- | --- |
| 提纲版（`--stage outline`） | 结构方案确认门前 | 事前核验：确认提纲即可逐条点开原文依据 | 演示元信息 + 页面规划表（事实要点带角标）+ 口径事项清单 | 事实有据/口径一致/无占位残留/素材清单齐/类型标注 |
| 成稿版（`--stage final`） | 交付时 | 事后溯源：成稿每页结论对应原文出处 | 最终演示的页面级结论文本（关键结论带角标） | 事实有据/质检通过/无占位残留/图表有来源注/口径一致 |

**核验诚实性原则与交付干净原则**：全部指标由脚本真实计算，不假装通过；**交付给用户的报告必须是「核验完成」的干净状态**——可修复问题（角标未绑定、JSON 结构不符、可补的原文链接、`self_check` 未写入）必须在交付前修复并重渲，不得带着可修复问题交付；只有不可抗力缺口（经权威官方入口核实确实无法补链、政策效力需人工复核）允许以温和提醒方式保留，且交付时向用户说明原因。

### 检索/合并 JSON 数据规范

- 多轮检索先合并为一个 JSON：`检索文章` 数组顺序与素材清单编号一致，`角标` 重排为清单编号（缺失时渲染器按数组位置 1..N 兜底，顺序不可乱、不可筛除未引用材料）。
- **无链接材料交付前必补（不可抗力除外）**：接口偶有材料不带 `源网址`——合并时逐条检查，**交付前必须先尝试人工补链**（经权威官方入口检索核实后补真实 URL，填 `源网址`/`policyUrl`，同步核实数据源名称）；只有确实无法找到官方链接的（材料下线、无公开 URL）才保留「无原文链接 · 需注意」提醒交付，并向用户说明原因。禁止伪造链接。
- **`self_check` 交付前必写**：提纲版与成稿版交付时，合并 JSON 必须写入 `self_check`（5 项如实结果）——「未记录」状态不应出现在交付物中。
- 每条材料按素材清单加 `类型` 字段（政策依据/数据支撑/参考案例/表述参考）——用于核验报告单「材料构成」指标与来源卡色系（绿/蓝/橙/灰）。
- 多路检索合并时给每条材料加 `搜索条件`（search_key，本路的阅读友好名，如「国家·政策」「青岛·数据」）——知识专库按其生成分组 tabs；**每条材料只保留其首路标签，禁止把多路标签拼接成一个**（拼接会造出「A、B」式假分组，过程回顾的"检索 N 路"随之虚高；需要保留多路归属时另写 `搜索条件全部` 列表字段）；**合并时保留接口原始字段不得丢弃**：`段落[].标题`（该段在原文件中的章节位置，渲染为多段分块面包屑链）、`发布日期可信度`（「高」=模型治理入库，渲染高可信徽标）、`screenShotPath`（接口存档快照，原文链接失效时兜底回看，渲染器自动处理无需改写）。
- 检索召回但正文未采用的相关材料（排除明显无关后）全量放入顶层 `recalled_materials` 数组——报告「未引用素材」分组展示，不占正文角标编号、不参与核验统计（其缺链不影响核验结论，卡上如实标注）。
- **同一篇文章只留一条**：合并时按「标题+源网址」去重（多路召回常带重复片段，重复录入会让报告出现成批同名卡——实测《医疗保障法》重复 17 张）。渲染器侧同口径兜底（归一化标题+网址，URL 去尾斜杠）；若同一篇文章确在清单里占多个编号（**同文异号**，如提纲第 3 页用 [8]、第 7 页用 [13]），渲染器会合并为**一张卡并并列显示全部编号**（`[8][13]`），正文引用任一编号都能定位，不会出现「未绑定」红项。
- 可选顶层字段：`self_check`（自检 5 项如实结果，键支持中文，值支持 `pass`/`通过：说明文字`/`✓`）、`verification_checks`（需人工复核事项，逐条透传）。**自检书写纪律**（对齐公文写作 3.7.3）：只允许五项标准键（事实有据/质检通过/无占位残留/图表有来源注/口径一致），值以显式「通过」或「未通过：原因」开头；核对说明、待办事项不得写成额外键（白名单外键渲染器忽略）也不得写成描述性值（无法识别按未记录处理不判红）；有未闭环项先补齐再写自检，不得带着未通过交付。
- **生成前硬校验**：素材非空而答案正文无 `[N]` 角标时脚本拒绝生成并报错（exit 2）——修正答案文件后重跑，不得绕过。

### 答案文件编制规范（两版通用）

- 落盘 `official-docs/search-results/`（脚本输入路径约束）：提纲版 `<项目短名>_outline.md`，成稿版 `<项目短名>_answer.txt`。
- 角标 `[N]` 对应素材清单检索编号（n＝该材料在素材清单/合并 JSON 里的 1-based 序号），**边写边标、禁止写完正文再回头反查补标**——渲染器只拦"越界角标"（[99] 无第 99 篇），拦不住"界内挂错"（正文写甲的内容却标 [3]，会绑定到丙的材料且核验单仍全绿）；**只能指向合并 JSON 中真实存在的素材**；每个数字、政策名、案例必须能通过角标回溯到来源原文；挂不上角标的事实删除表述、降为概括表述，提纲版还可列入口径事项清单标注「待补检索」——不得裸写。
- **用户提供的不可核验素材禁止挂角标**（无对应检索材料，幽灵角标会被核验报告单判为未绑定红色警示、核验不通过）；以文字标注「用户提供 · 未经权威核验」并写入口径事项清单，交付时提醒复核。
- 口径事项清单（提纲版专属）：统计口径差异、外省材料定位、待补检索项，逐条带角标；纯用户材料要点标注「用户提供 · 未经权威核验」。
- Markdown 表格按 GFM 语法书写（分隔行每格 ≥1 短横线即可，`| -- | ---- |` 也识别）；≥4 列宽表自动横向滚动。

### 交付

- 两版报告均归档到项目 `exports/`（提纲版在项目创建后归档），随 `.pptx` 三件套一并交付；免检索模式两版均不生成。
- 素材与页面的映射以内容包素材清单为准。
- **同指标口径冲突检测**（对齐公文写作 3.7.1）：同一指标在多份材料出现多个取值时，按材料发布日期取最新官方口径采用，禁止不加比对采用任一数值；官方更新产生的新旧取值不算矛盾（按最新口径采用，并在页面备注或交付说明中如实反映口径调整时间）；无法用日期与权威性裁决的才降级为「口径待确认」列入口径事项清单。
- **文号只允许标准格式**：`文号` 字段值必须是标准发文字号（含〔年份〕序号号，如「国办发〔2024〕52号」）；禁止把「中办、国办 2026 年印发」类描述性文字当文号写入（渲染器按格式校验，非标准文号当无文号处理不显示）。
- **转换产物字段原样复制**：合并 JSON 整理时，`文号`、`screenShotPath`（快照链接）与 `段落`（含段落标题）从 MCP 转换产物或检索产物对应材料**原样复制不得丢弃**（实测走样：转换产物有 24/130 条快照，整理后全空）。
- **选材优先发文版与文号回填**（对齐公文写作 3.7.2，文号丢失根治）：检索库对同一政策文件常存多个抓取条目（新闻稿版「联合印发」与发文版「关于印发…的通知」），文号挂在发文版条目上、新闻稿版为空——选材时**发文版占优**（带文号 > 带快照 > 源网址为权威门户）；整理合并 JSON 时政策类材料从检索结果 `policyFiles` 逐条核对，所选条目 `writtenText` 为空则从同文件其他变体条目回填 `文号` 字段，只认检索返回的真实文号、不得猜测。
- 报告是辅助核验文件，明确告知用户「不是正文附件」。

## 四、禁止事项

- 不得把检索材料原文整段塞进幻灯片（幻灯片是提炼不是粘贴）。
- 不得用主题相近但未支撑该页结论的材料。
- 不得伪造数据、文号、政策名称、来源链接。
- 未执行检索时不得声称素材来自深知可信检索。
- 外部 Web 检索默认禁用；用户明确要求改用外部搜索时，须说明该素材不能作为深知素材、不进溯源核验报告。
