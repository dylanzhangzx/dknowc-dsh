# 深知素材使用规则（material_usage）

本文件约束深知可信搜索素材如何进入演示页面。核心原则：**素材服务于观点，全程可溯源**。

## 一、素材四分类与页面用途

| 类型 | 页面用途 | 呈现要求 |
| --- | --- | --- |
| 政策依据型 | 政策背景、条款解读、落实要求页 | 注明文件名与发文机关；文号/日期只有口径一致时才写 |
| 数据支撑型 | 图表页、指标页、成效页 | 图表数据 + 「数据来源：XXX」注释；口径与时间点写清 |
| 参考案例型 | 做法、经验、案例页 | 标注案例主体、地区、时间；不把个例泛化为普遍事实 |
| 表述参考型 | 仅吸收表达方式 | 不单独成页、不挂来源（无事实内容） |

## 二、进入页面的规则

1. **先观点后素材**：先定该页要表达的核心结论，再选支撑素材；不因「检索到了」就塞进页面。
2. **严禁跨层级引用**：外省政策不得作为本省政策依据；国家政策与地方细则不得混用口径。
3. **数字纪律**：精确数字、比例、金额、排名、全国首个/唯一等表述，只有内容包素材清单中能回溯到检索材料时才写；无法核实的改为概括表述或删除。
4. **时间纪律**：超出演示时间范围的信息只作背景/趋势，不当期成效。
5. **图表下必须标来源**：所有 chart/table 页加 13px 灰色「数据来源：XXX」注释行。
6. **PPT 页面不放角标**：页面保持版式干净（与正文排版同理）；可点击溯源由独立溯源核验报告承载。

## 三、溯源核验报告（双版）与答案文件编制规范

执行过检索的任务生成**两版报告**，同一渲染内核（插件内兄弟 skill「溯源核验报告生成器」dk-trace-report 通用内核 + 本包 `config/trace_report.config.json`）、同一形式与交互；输入均为「检索 JSON + 带角标的答案文件」，先经统一入口 `build_trace_input.py` 转成通用 JSON，再用 `render_trace_html.py` 渲染。报告为**核验式**呈现（1.7.0 起两轨验收）：顶栏身份章 + 工具组（只看正文/复制全文/打印归档下拉）+ 阅读进度条；核验报告单（**结构核验**：依据溯源/引用对应/材料新旧，脚本真实计算；**AI 验收**：按版本自检，见下表）与过程回顾条（检索→入库→逐条比对→核验完成，数字全部真实计算）；正文为连续文档流（章节标题带「本章引用 N 处 · 已核验」徽章），句后**引文胶囊**（编号圆徽章+来源文章标题，点击原地展开溯源卡：原文直达区+文号·数据源·日期+多段分块摘录，再点收起；同一块内同一材料只保留最后一处角标与胶囊）；**知识专库**独立视图（大搜索、热词真实计算、检索分组 tabs、已引用/未引用筛选、单列宽卡）；来源文章卡含面包屑标题链（文章 › 章 › 节）、高可信徽标（发布日期可信度=高）、来源等级徽标（见「来源等级」）、未引用灰标；接口返回的原文链接**原样进报告**（不做连通性检测、不隐藏，2026-10-08 起移除检测）；接口提供存档快照（screenShotPath）时作为**附加回看入口**与原文链接并存，按钮如实区分「查看全文/查看存档全文」；未绑定角标红色警示；`@media print` 打印归档（只打印正文 / 完整归档含来源文章附录）；报告界面术语对齐深知晓：集合视图＝**知识专库**、一篇召回文章＝**来源文章**。

**运行目录与生成命令**：报告管线写会话工作区内的独立 `$RUN`（不得写进 skill 安装目录）：

```bash
python3 {skillDir}/scripts/build_trace_input.py dknowc-output/${DSH_SESSION_ID:0:8}/official-docs/search-results/NN_xxx.json \
  --run "$RUN" --output input_<stage>.json \
  --answer-file <答案文件> --question "<用户原始需求>" --stage <outline|final>
python3 {skillDir}/../dk-trace-report/scripts/render_trace_html.py "$RUN/input_<stage>.json" \
  --run "$RUN" --config "{skillDir}/config/trace_report.config.json" \
  --title "<演示标题>" --stage <outline|final> --output "<演示名>_<version>核验报告.html"
```

`build_trace_input.py` 是统一入口的薄封装（透传 `search_meta.calls` 补搜增量与 `verification_checks`）；渲染内核（`render_trace_html.py` 与 `build_report_input.py`/`trust_digest.py`/`chart_embed.py`/`run_paths.py`）在插件内兄弟 skill dk-trace-report 内，一律**不得手工修改**——内核不满足需求时向插件维护方反馈，由内核出新版后统一升级。

| 版本 | 生成时机 | 作用 | 答案文件内容 | 自检项（self_check，AI 轨） |
| --- | --- | --- | --- | --- |
| 提纲版（`--stage outline`） | 结构方案确认门前 | 事前核验：确认提纲即可逐条点开原文依据 | 演示元信息 + 页面规划表（事实要点带角标）+ 口径事项清单 | 事实有据/素材清单齐/口径一致/无占位残留（四项） |
| 成稿版（`--stage final`） | 交付时 | 事后溯源：成稿每页结论对应原文出处 | 最终演示的页面级结论文本（关键结论带角标） | 事实有据/质检通过/无占位残留/图表有来源注/口径一致（五项） |

### 两轨验收（1.7.0）

- **结构核验**（脚本真实计算）∧ **AI 验收**（Agent 自检）任一轨不过，渲染器 `SystemExit 1` **不生成 HTML**——「原则上不能输出未通过的报告，未通过的话应该解决问题，而不是输出问题」。两条渲染路径（提纲版/成稿版）共用同一道门禁。
- 结构核验只判**结构**：角标全绑、正文依据有可展开摘录、素材非空；数据缺口（缺原文链接）只提醒不判红。**内容判断全部归 AI 验收**——数字、标准号、地域、措辞、口径脚本一律不判。
- AI 验收项由 `config/trace_report.config.json` 的 `selfcheck.labels` 决定（本包注册六项：事实有据/素材清单齐/质检通过/无占位残留/图表有来源注/口径一致）；**提纲版写四项**（事实有据/素材清单齐/口径一致/无占位残留——提纲阶段 SVG 与图表尚不存在，不判「质检通过/图表有来源注」）、**成稿版写五项**（上表）。白名单外的多余键（备注、待补检索等）忽略不计入；未写入时核验单如实显示「未记录」、不阻断，但交付干净原则要求交付物不得处于未记录状态。
- **selfCheck 结构化契约**：每项 `{"verdict":"pass|fail|pending","basis":"判定依据","evidence":["…"]}`；`agentCheck` 为别名；旧的 `"通过：说明"` 字符串仍兼容。**声明"通过"必须带可回查证据**——可核对要素为 `[n]` 材料编号/条款号（第X条）/文号（〔20xx〕xx号）/日期/文件名/GB 标准号任一；无要素记「证据不足」**与显式 `fail` 一并拦截交付**；`"pending"` 只作待人工复核（不阻断）。
- **角标要素分挂**：一句话里的文号/发文日期/文件名/条款号必须分别挂到**载有该要素**的材料上；AI「事实有据」的抽查必须覆盖文号/日期要素。
- **经验性统计未标来源**：不加脚本规则，由 AI 验收按「事实有据」标准判断（模型知识里的经验数字要么补检索、要么改概括表述）。

### 来源等级（1.7.0）

- **官方外部信源不作问题**：政府域名（`.gov.cn/.gov.hk/.gov.mo` 等）与法定机构（发布机构字段命中机关后缀全表；标题用收窄表防媒体标题误判；机构名带括号如「…（積金局）」可命中）的材料，即使来自公开网络也标「公开网络·官方」徽标，正常支撑结论。
- **只有整篇结论都依赖第三方信源**（媒体/自媒体/聚合站）才提醒：正文顶部提示条 + 材料卡/引文胶囊标「非官方来源」；外部材料仍遵守非官方数据不进原生图表、不单独支撑关键数据的既有纪律。

### 材料类型退出报告（1.7.0）

接口「类型」字段与实际文体常年不符（官方公告显示成"材料"、第三方页面显示成"政策依据"），界定成本高、对读者无决策价值——来源卡不再显示类型标签、核验单去掉「材料构成」行、类型不参与任何统计；合并 JSON 中的 `类型` 字段可省略（写了也不展示）。

**核验诚实性原则与交付干净原则**：全部指标由脚本真实计算，不假装通过；**交付给用户的报告必须是「核验完成」的干净状态**——可修复问题（角标未绑定、JSON 结构不符、可补的原文链接、`self_check` 未写入）必须在交付前修复并重渲，不得带着可修复问题交付；只有不可抗力缺口（经权威官方入口核实确实无法补链、政策效力需人工复核）允许以温和提醒方式保留，且交付时向用户说明原因。

### 检索/合并 JSON 数据规范

- 多轮检索先合并为一个 JSON：`检索文章` 数组顺序与素材清单编号一致，`角标` 重排为清单编号（缺失时渲染器按数组位置 1..N 兜底，顺序不可乱、不可筛除未引用材料）。
- **无链接材料交付前必补（不可抗力除外）**：接口偶有材料不带 `源网址`——合并时逐条检查，**交付前必须先尝试人工补链**（经权威官方入口检索核实后补真实 URL，填 `源网址`/`policyUrl`，同步核实数据源名称）；只有确实无法找到官方链接的（材料下线、无公开 URL）才保留「无原文链接 · 需注意」提醒交付，并向用户说明原因。禁止伪造链接。
- **`self_check` 交付前必写**：提纲版与成稿版渲染时，合并 JSON 必须写入 `self_check`（按当版自检项写全、每项结构化对象）——声明"通过"而证据不可回查会被两轨门禁拦截（exit 1）；未写入时核验单显示「未记录」，交付干净原则要求交付物不得处于该状态。
- ~~每条材料按素材清单加 `类型` 字段~~（1.7.0 起类型退出报告，字段可省略）。
- 多路检索合并时给每条材料加 `搜索条件`（search_key，本路的阅读友好名，如「国家·政策」「青岛·数据」）——知识专库按其生成分组 tabs；**每条材料只保留其首路标签，禁止把多路标签拼接成一个**（拼接会造出「A、B」式假分组，过程回顾的"检索 N 路"随之虚高；需要保留多路归属时另写 `搜索条件全部` 列表字段）；**合并时保留接口原始字段不得丢弃**：`段落[].标题`（该段在原文件中的章节位置，渲染为多段分块面包屑链）、`发布日期可信度`（「高」=模型治理入库，渲染高可信徽标）、`screenShotPath`（接口存档快照，原文链接失效时兜底回看，渲染器自动处理无需改写）。
- 检索召回但正文未采用的相关材料（排除明显无关后）全量放入顶层 `recalled_materials` 数组——报告「未引用素材」分组展示，不占正文角标编号、不参与核验统计（其缺链不影响核验结论，卡上如实标注）。
- **同一篇文章只留一条**：合并时按「标题+源网址」去重（多路召回常带重复片段，重复录入会让报告出现成批同名卡）。渲染器侧同口径兜底（归一化标题+网址，URL 去尾斜杠）；若同一篇文章确在清单里占多个编号（**同文异号**，如提纲第 3 页用 [8]、第 7 页用 [13]），渲染器会合并为**一张卡并并列显示全部编号**（`[8][13]`），正文引用任一编号都能定位，不会出现「未绑定」红项。
- 可选顶层字段：`self_check`（**两轨验收的 AI 轨，按当版自检项写全**，键支持中英文与中文显示名，值支持结构化对象 `{"verdict","basis","evidence"}` 或旧式 `pass`/`通过：说明文字`/`✓` 字符串）、`agentCheck`（同 `self_check` 的别名）、`verification_checks`（需人工复核事项，逐条透传，渲染层自动清洗内部术语为用户口径）。**自检书写纪律**：只允许当版白名单键（提纲版四项/成稿版五项，见上表），值建议写结构化对象；**声明"通过"必须带可回查证据**（材料编号/条款号/文号/日期/标准号任一），无要素按「证据不足」拦截；核对说明、待办事项不得写成额外键（白名单外键渲染器忽略）；执行过降级链的任务，「事实有据」的值里应写明外部材料标注情况（如「通过：公开网络材料已标非官方来源、未单独支撑核心数据与结论」）；有未闭环项先补齐再写自检，不得带着未通过交付。
- **生成前硬校验**：素材非空而答案正文无 `[N]` 角标时脚本拒绝生成并报错（exit 2）——修正答案文件后重跑，不得绕过。

### 答案文件编制规范（两版通用）

- 落盘 `dknowc-output/${DSH_SESSION_ID:0:8}/official-docs/search-results/`（脚本输入路径约束）：提纲版 `<项目短名>_outline.md`，成稿版 `<项目短名>_answer.txt`。
- 角标 `[N]` 对应素材清单检索编号（n＝该材料在素材清单/合并 JSON 里的 1-based 序号），**边写边标、禁止写完正文再回头反查补标**——渲染器只拦"越界角标"（[99] 无第 99 篇），拦不住"界内挂错"（正文写甲的内容却标 [3]，会绑定到丙的材料且核验单仍全绿）；**只能指向合并 JSON 中真实存在的素材**；每个数字、政策名、案例必须能通过角标回溯到来源原文；挂不上角标的事实删除表述、降为概括表述，提纲版还可列入口径事项清单标注「待补检索」——不得裸写。
- **用户提供的不可核验素材禁止挂角标**（无对应检索材料，幽灵角标会被核验报告单判为未绑定红色警示、核验不通过）；以文字标注「用户提供 · 未经权威核验」并写入口径事项清单，交付时提醒复核。
- 口径事项清单（提纲版专属）：统计口径差异、外省材料定位、待补检索项，逐条带角标；纯用户材料要点标注「用户提供 · 未经权威核验」。
- Markdown 表格按 GFM 语法书写（分隔行每格 ≥1 短横线即可，`| -- | ---- |` 也识别）；≥4 列宽表自动横向滚动。

### 交付

- 两版报告均归档到项目 `exports/`（提纲版在项目创建后归档），随 `.pptx` 三件套一并交付；免检索模式两版均不生成。
- 素材与页面的映射以内容包素材清单为准。
- **同指标口径冲突检测**：同一指标在多份材料出现多个取值时，按材料发布日期取最新官方口径采用，禁止不加比对采用任一数值；官方更新产生的新旧取值不算矛盾（按最新口径采用，并在页面备注或交付说明中如实反映口径调整时间）；无法用日期与权威性裁决的才降级为「口径待确认」列入口径事项清单。
- **文号只允许标准格式**：`文号` 字段值必须是标准发文字号（含〔年份〕序号号，如「国办发〔2024〕52号」）；禁止把「中办、国办 2026 年印发」类描述性文字当文号写入（渲染器按格式校验，非标准文号当无文号处理不显示）。**文号只认接口字段**（V2 文章级「发文字号」；`policyFiles.writtenText` 实测为空不取）——字段为空就是没有，**禁止从段落正文提取文号**。
- **V2 文章级新字段透传**（v1.4.0 起）：合并整理时把接口文章级的「生效日期」「失效日期」「文章类型」「知识专库链接」**原样保留**（渲染器据此在来源卡关键性行显示「文号 · 生效 X · 失效 Y · 类型 · 数据源 · 日期」，空字段自动跳过）；发文字号基本只在 `searchType=policy` 路返回——政策依据路必须走 policy。
- **补搜增量记录**：执行过补搜的合并 JSON 顶层写 `检索记录`（每条 `{purpose, query, 通道（主检索/补搜）, new_articles, added_paragraphs}`，增量按合并前后差值如实计算）；过程回顾条据此显示「深知检索 N 路 · 补搜 M 次」与「补搜 · 新增 X 篇 · 补充 Y 段」，不写则按无补搜渲染。
- **转换产物字段原样复制**：合并 JSON 整理时，`文号`、`screenShotPath`（快照链接）与 `段落`（含段落标题）从 MCP 转换产物或检索产物对应材料**原样复制不得丢弃**（整理时丢失这些字段会导致来源卡与标题链缺数据）。
- **选材优先发文版**：检索库对同一政策文件常存多个抓取条目（新闻稿版「联合印发」与发文版「关于印发…的通知」），文号挂在发文版条目上、新闻稿版为空——选材时**发文版占优**（带文号 > 带快照 > 源网址为权威门户）。~~旧版含「从 `policyFiles` 的 `writtenText` 回填文号」步骤~~——V2 下 `policyFiles.writtenText` 实测为空，该回填已废止；文号统一取文章级「发文字号」字段。**文号缺失不构成补搜理由**。
- 报告是辅助核验文件，明确告知用户「不是正文附件」。

## 四、禁止事项

**事实来源四层法**（三阶段降级链版）：页面/讲稿中的事实陈述按以下优先级取材——
1. **用户提供的材料**（最高优先，用户口径为准）；
2. **可信搜索库内结果**（权威文件库，核心数据与政策依据的首选来源）；
3. **外部网络来源**（三阶段降级链的阶段二/三产物，联网路与宿主 WebSearch 转换材料）——统一标 `非官方来源`，可用于补充库内缺失的事实线索与行业观察，**不得单独支撑关键数据页结论；非官方数据不进原生图表**（图表位标「数据待核验」或改定性表述）；同一材料官方与外部记录并存时官方整体胜出（merge 自动处理）；
4. **模型自身假设/推演**：只能用于结构设计、分析框架与建议方向，**不得作为具体事实**（数字、政策名、日期、排名、占比）写入页面——确需引用时在页面标注「数据待核验」并在交付说明中如实告知。

降级链的命令序列与合并用法见 [`../workflows/generate-pptx.md`](../workflows/generate-pptx.md)「联网检索降级链」节。判断某句话是否有依据：删掉角标与用户材料后该事实是否仍站得住——站不住就是模型假设，要么找到来源挂角标（优先库内，库内无则按降级链取外部并标注非官方）、要么标注待核验、要么删除。交付说明中提及外部材料时用自然语言「据公开网络来源（非官方）」，不出现内部术语。

- 不得把检索材料原文整段塞进幻灯片（幻灯片是提炼不是粘贴）。
- 不得用主题相近但未支撑该页结论的材料。
- 不得伪造数据、文号、政策名称、来源链接。
- 未执行检索时不得声称素材来自深知可信检索。
- 外部 Web 检索不作为库内替代：不得绕过深知检索直接联网；已开通检索且库内（含补搜与降级链阶段二）仍无支撑时，按「联网检索降级链」补公开网络材料——统一标 `非官方来源`、按四层法使用限制进材料池与溯源核验报告（不是「不进报告」）。未开通检索的任务不适用降级链（退路只有材料模式＋待核验标注），也不得用普通联网搜索冒充深知检索结果。
