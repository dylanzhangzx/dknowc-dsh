# 内容包规范（content-pack）

内容包是深知内容层与 SVG 生成层之间的桥梁：把**带来源的可信素材**固化为**带页面规划的演示叙事**，经用户确认后再进入逐页 SVG 创作。文件保存为项目根的 `content-pack.md`。

## 一、内容包结构

```markdown
# <演示标题> 内容包

## 1. 核心信息
- 一句话主张（这份 PPT 要让对方记住的唯一结论）
- 受众与场合（谁看、什么场合、多长时间）
- 叙事模式（如：总-分-总 / 问题-原因-对策 / 时间线 / 对比论证）

## 2. 页面规划
| 页 | 类型 | 标题/主题 | 要点与素材 | 来源 |
| -- | ---- | -------- | ---------- | ---- |
| P01 | cover | ... | ... | — |
| P02 | agenda | ... | ... | — |
| P03 | content | ... | 观点 + 支撑素材ID | [M3][M7] |
| P04 | chart | ... | 数据 + 图表类型 | [M12] |
| ... | | | | |

## 3. 素材清单（带来源）
- [M3] 政策依据型：《文件名》（发文机关，日期）——可支撑的结论
- [M7] 数据支撑型：指标=数值（口径、时间点，来源）
- [M12] 参考案例型：案例主体、地区、时间、做法、结果
- [M15] 表述参考型：仅吸收表达方式

## 4. 风格预设
- 选定：gov-simple（或用户指定）
- 画布：ppt169
- 确认记录：用户在结构方案确认门确认/调整的内容
```

## 二、编制规则

1. **先叙事后分页**：先定核心信息与叙事模式，再把论证拆成页面序列；页面顺序服务论证，不照抄素材顺序。
2. **一页一观点**：每页「类型 + 标题 + 要点」必须能回答「这页想让观众记住什么」。常见页类型：cover / agenda / section / content / chart / table / timeline / comparison / closing。
3. **每个事实挂来源**：页面规划表中每页的素材都标注素材ID；素材清单中每个素材必须能回溯到检索结果 JSON 的具体材料（标题、来源、链接）。无法挂来源的事实删除或改为概括表述。
4. **密度匹配风格**：页面要点数与风格预设的密度纪律一致（gov-simple 每页≤5条，gov-data 每页一图一结论）。
5. **数字进图表**：内容包阶段就明确哪些数据上图表（chart/table 页）、用哪种图；数据与口径写进素材清单。
6. **演讲备注可选**：如需备注（notes），在页面规划的行内备注列写每页讲稿要点。

## 三、与检索的关系

- 内容包的素材清单来自 `trusted_search.py` 检索结果（`official-docs` 工作区 JSON）；素材ID 在生成可信溯源核验报告（提纲版与成稿版）时用于角标对应，多轮检索以素材清单编号为角标唯一基准。
- 检索未覆盖的关键缺口：回到检索方案确认门补检索，不得用无来源内容填补。
- 用户提供自带材料：进入 `sources/`，在素材清单标注「用户提供」，可信溯源核验报告中单独分组。

## 四、确认与变更

- 内容包 + 风格预设 + 提纲版可信溯源核验报告一起构成「结构方案确认门」的展示内容；未确认不开项目、不写 SVG。
- 用户调整（增删页、换风格、改叙事）后更新内容包与提纲答案文件、重新生成提纲版报告，再确认，不留口头变更。
- SVG 创作期间如需偏离内容包（临时改标题、调页序），必须先改内容包再改 SVG，保持三者一致：检索 JSON ↔ 内容包 ↔ SVG。
